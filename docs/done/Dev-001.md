# Dev-001: Replayable Simulation and Persistent Work

[Architecture] [Engine] [Migration]

Close the simulation debts around replay, actor movement and interrupted activities. Keep the engine
as the only state writer and make all outcomes reproducible by replaying the recorded input stream.
The design decisions are recorded in `utils/VISION.md` [Sec. 5], [Sec. 7] and [Sec. 11].

## 1. Input journal and replay

- [x] Add a numbered SQLite migration for an append-only input journal, separate from gameplay
      events. Store deterministic sequence, input kind and serialized payload; run-length encode
      adjacent identical commands. Never store wall-clock timestamps.
- [x] Record state-mutating commands in engine-processing order, including initial seed/generator
      options, moves and their simulation-time deltas, actions and clock changes. Read-only queries
      are not replay inputs. Record rejected commands as no-op inputs without emitting gameplay events.
- [x] Add a replay runner that starts from the recorded initial world and resubmits inputs through
      the same `WorldEngine` API. It must not write snapshots or event outcomes directly.
- [x] Prove replay produces the same final state and committed event stream as the original run,
      including moves below tile resolution and commands rejected by validation
      (`InputReplayRules.cs`).

## 2. Actor movement and collision

- [x] Resolve actor-body overlap in `sim.engine` using the same 0.3 m body radius and standing
      intervals as terrain movement. Sort candidate actor checks by stable actor ID.
- [x] Actor contact blocks movement only; it never pushes, damages or writes from a subscriber.
      Permit an already-overlapping actor to move out without making the overlap worse.
- [x] Fix the alternating diagonal slide when a held move meets a blocked edge. Keep the existing
      edge clearance and step rules, and resolve every sub-step deterministically.
- [x] Add actor-overlap and escape cases plus the blocked-edge regression to `ActorMovementRules.cs`;
      re-run action scenario parity goldens.

## 3. Resumable activity work

- [x] Let only productive-work handlers (`dig`, `build`) persist accumulated game time by actor and
      canonical action/target. Use a numbered migration; do not infer progress from wall-clock time.
- [x] Interrupting an activity saves earned work without applying partial world changes. Reissuing
      the same action resumes that work only after the normal engine validation succeeds.
- [x] Clear saved work on successful completion; prevent stale work from applying to a changed or
      invalid target. Preserve progress across save/restart.
- [x] Test interruption, save/restart, failed revalidation and resumed completion in
      `ActivityProgressRules.cs` and migration tests. Preserve normal restart behavior for `wait` and travel.

## 4. Boundaries

- `WorldEngine` remains the only writer of simulation state and journal rows.
- The input journal is not an event bus and rejected inputs do not emit gameplay events.
- Godot and `System.Random` do not participate in replay or movement decisions.
- No game module creates its own private movement/action path.
- Update every touched module version by `0.0.1`; update the system map only if the implementation
  adds a new persisted flow or changes module boundaries.

## 5. Acceptance

- `InputReplayRules.cs`, `ActorMovementRules.cs`, `ActivityProgressRules.cs` and migration tests pass;
  action scenario goldens
  remain stable except for reviewed, explained movement outcomes.
- A replay from a clean generated world reproduces state and stored events exactly.
- A blocked movement test shows no alternating lateral displacement; actor contact remains
  deterministic across save/restart.
- Interrupted work resumes after reload, while failed revalidation has no world effect.
- `npm run check` passes.

# Dev-010: Asphalt texture (BitCanvas + game)

[Art pipeline] [Tooling] [Rendering]

The test world's road (`world/gen/testworld.py`, `120 <= gx <= 123`) is `asphalt`, and the game
draws it as a flat `#414449` diamond because no sheet exists for it. BitCanvas has no asphalt
material (concrete has a palette *named* "Asphalt", which is only a dark concrete ramp). This doc
adds an `asphalt` material to BitCanvas, generates its two sheets and wires them into the game.

It also closes the concrete fix made on 23/09/2026 in chat: `terrainSprites.ts` and
`terrainSheets.ts` now point `concrete` at `floor/concrete_x4.png` / `floor/concrete_side_x4.png`
instead of the stone sheets, but `web.game` was not version-bumped. The bump here covers both.

Reference: `docs/done/Dev-009.md` (BitCanvas structure, [Sec. 3.3] export names, [Sec. 3.4] send
to game); `docs/done/Fix06.md`, `docs/done/Fix09.md` (sheet formats); `CONTEXT.md` (web.game,
"Assets outside `web/` must be static imports", BitCanvas pitfall).

## 1. Decisions to approve

| Topic | Decision | Why |
|---|---|---|
| BitCanvas key | New terrain material `asphalt`, listed after `concrete` | Same key as the world material, so nothing needs mapping |
| Game files | `floor/asphalt_x4.png` (256×32) and `floor/asphalt_side_x4.png` (128×32) | `floor/` already holds the other paved surfaces (`concrete`, `stone`), and `gamesync.js` already accepts it. A `road/` folder can come if road markings ever need their own sheets |
| Look | Dark, low-contrast base with worn broad patches and a dense single-pixel speckle: light aggregate stones and dark pores. No joints, no cracks, no markings | That is what reads as asphalt at 64×32. Cracks and lane lines are per-location details, not per-tile noise; tiling them across a road would repeat visibly |
| Sides | Reuse the generic side path (the one concrete uses): the face samples the same `materialLevel` formula, the cap's first row copies the top edge | A slab edge of asphalt is the same aggregate; no special code |
| Palettes | Four asphalt ramps [Sec. 2.2], the first one centred on the world colour `#414449` | The game tints sprites relative to the material colour, so the default sheet sits right at that tone |
| Concrete's "Asphalt" palette | Renamed to `Charcoal` / `Dark charcoal`. Ramp unchanged | Two "Asphalt" labels in one tool is confusing. The label does not affect pixels |
| Density and dirt | Not shown for asphalt (they stay `grass-only`) | Same as the other paved materials |
| Default sheets | The implementer generates the committed sheets with seed `A17F3C` and the first palette (`Fresh`), brightness 58 | Reproducible; the user can regenerate with any seed through "Send to game" |

## 2. What changes

### 2.1 `bitcanvas` (v0.0.1 → v0.0.2)

`BitCanvas/app.js`:

- `materialPalettes.asphalt` [Sec. 2.2].
- `materialPalettes.concrete.autumn`: `name: 'Charcoal'`, `detail: 'Dark charcoal'`.
- `GAME_SHEETS.asphalt = { folder: 'floor', variants: 'asphalt_x4.png', sides: 'asphalt_side_x4.png' }`.
- `materialLevel`: a new `else if (material === 'asphalt')` branch **before** the final `else`
  (that `else` is cobblestone; anything unknown falls into it today):

  ```js
  } else if (material === 'asphalt') {
    const worn = isoNoise(x + 0.5, y + 0.5, 5, 5, seed);
    const fine = isoNoise(x + 0.5, y + 0.5, 17, 13, seed ^ 0x165667b1);
    const grain = materialCellHash(x, y, seed ^ 0x3c6ef372) % 100;
    level = 3.5 + (worn - 0.5) * 0.8 + (fine - 0.5) * 0.5 + brightness;
    if (grain < 9) level += 1.6;        // light aggregate stone
    else if (grain < 13) level -= 1.2;  // pore
    else if (grain === 99) level += 3;  // rare bright chip
  }
  ```

  The per-pixel hash needs no tiling (it has no structure to break at a seam); `isoNoise` already
  wraps. The Bayer dither in `createMaterialTile` stays as it is for all materials.
- `createSideCell`: no change. Asphalt takes the generic branch (`surfaceX = x`,
  `surfaceY = faceRow`), like concrete.
- `updateMaterialControls` `materials` table: `asphalt: { title: 'Asphalt texture', subtitle:
  'Road surface', corner: 'ROAD ASPHALT', description: 'Dark bitumen with fine aggregate speckle and worn patches.' }`.
- `randomMaterialPalette`: asphalt hue `[195, 235]`, saturation `[2, 10]`, and a darker lightness
  span for asphalt only: `8 + step * 46` instead of `13 + step * 58`. Other materials keep the
  current formula exactly.

`BitCanvas/index.html`: one row after the concrete button, same markup as its neighbours:
`id="asphalt-material"`, `data-material="asphalt"`, icon `▩`, `<b>Asphalt</b>`,
`<small class="meta">floor/asphalt_x4</small>`. Arrow-key navigation picks it up automatically
(it walks `.material-option:not([hidden])`).

`BitCanvas/gamesync.js`: no change (it already accepts `floor/`).

### 2.2 Asphalt palettes

Eight steps, darkest to brightest. `ramp[2]`/`ramp[3]` bracket the world colour `#414449`
(65, 68, 73) in `meadow`.

| Key | Name | Detail | Ramp |
|---|---|---|---|
| `meadow` | Fresh | New blacktop | `[[18,19,22],[28,30,34],[40,42,47],[54,57,62],[70,73,79],[90,93,99],[116,119,124],[150,152,155]]` |
| `emerald` | Worn | Faded gray | `[[30,31,33],[44,46,49],[59,61,65],[75,78,82],[93,96,100],[114,117,120],[139,141,143],[168,169,169]]` |
| `moss` | Bleached | Sun-baked | `[[40,38,35],[56,54,50],[73,71,66],[91,89,84],[111,108,102],[133,130,123],[158,155,147],[186,182,172]]` |
| `autumn` | Wet | Rain-dark | `[[14,16,21],[22,25,32],[32,36,45],[44,49,59],[58,64,75],[76,83,95],[100,108,120],[132,140,150]]` |

The base level was planned at 2.6 and raised to 3.5 during implementation: at 2.6 the default
sheet averaged (52, 55, 60), at 3.0 (57, 59, 65), at 3.5 (65, 68, 74), which matches the flat
`#414449` road it replaces. Most pixels land on `ramp[3..4]`, speckle on `ramp[5]`, pores on
`ramp[2]`.

### 2.3 Sheets (`src/sprites/floor/`)

Generate `asphalt_x4.png` and `asphalt_side_x4.png` from BitCanvas with the [Sec. 1] defaults.
Either "Send to game" into the real `src/sprites/`, or the download buttons (their names already

Both files are committed. They must exist before [Sec. 2.4], or the Vite build and
`terrain-sprites.test.ts` fail.

## 3. What must not break

- Grass, planks, cobblestone and concrete output stays byte-identical for the same inputs
  (the new branch sits before cobblestone's `else`; nothing else in the generation path changes).
- Concrete keeps rendering with `concrete_*` sheets; wood and grass unchanged.
- BitCanvas still opens from `file://` with no build; furniture tab untouched.
- The server and `materials.toml` are not touched (`asphalt` already exists there).

## 4. Acceptance

1. Before editing, export the variants atlas and side sheet for grass, planks, cobblestone and
   concrete (seed `A17F3C`, first palette, brightness 58, density 6). After the change, repeat;
   SHA-256 of each pair matches (`certutil -hashfile <file> SHA256`).
2. BitCanvas lists Asphalt after Concrete; all three views (tiles, block, sides) render it; the
   four palettes show the [Sec. 2.2] names; concrete's fourth palette reads "Charcoal"; `P`
   (random palette) on asphalt yields a dark, near-neutral ramp; `↑`/`↓` reach it.
3. The tiles view shows no seam between neighbouring asphalt diamonds; the sides view shows the
   cap's top row matching the tile edge.
4. `src/sprites/floor/asphalt_x4.png` is 256×32 and `asphalt_side_x4.png` is 128×32.
5. In the game, the road at x 120–123 is textured, its tone close to the old flat road; road edges
   with a height step show the side sheet. Concrete floors in the test building show concrete,
   not cobblestone.
6. `cd web && npm test && npm run build` passes.

## TL;DR

Adds an `asphalt` material to BitCanvas (dark speckled road surface, four palettes, generic side
path), generates `floor/asphalt_x4.png` and `floor/asphalt_side_x4.png`, and wires them into the
game so the test road stops being a flat colour. Bumps `bitcanvas` to v0.0.2 and `web.game` to
v0.1.8, the latter also covering the concrete-sheet fix. Existing materials stay byte-identical.

# Dev-019: Framed viewport and view tabs (Game, Debug, LLM)

[Feature] [UI] [Refactor] [Accessibility]

Today the Phaser canvas fills the window (inset 8 px) and every tool floats over it: the HUD, the
`DEBUG` drawer that slides in from the right, the popovers. This doc reshapes the shell into a
frame: the viewport sits in the centre with a ~20 px margin on every side, and a tab strip in the
top-left corner of that frame switches what the framed area shows: `GAME` (the world and its HUD),
`DEBUG` (the map generator form, now full size instead of a drawer) and `LLM` (a placeholder for the
model log that Phase 3 will fill). No server change.

Reference: `docs/utils/STYLEGUIDE.md` [Sec. 1] (layers), [Sec. 5] (HUD placement), [Sec. 14]
(drawer and tabs), [Sec. 16] (keyboard paths, 1280×720 minimum); `docs/utils/VISION.md` [Sec. 11]
(every model decision is logged as an event) and [Sec. 13] (LLM layer).

## 0. Current state (measured before this doc)

- `App.tsx` renders `<main class="shell">` with `.world` (Phaser parent) and `.hud` both at
  `position: absolute; inset: 8px`. `.shell::before` draws the cyan corner brackets at 2 px and
  `.shell::after` the centred `ETHERBOUND // LIVE SIMULATION` label.
- `createGame` builds Phaser with `Scale.RESIZE`, so the canvas follows its parent's size.
- The `DEBUG` button in the status pills toggles `DebugDrawer` (`.drawer`, fixed, right side,
  360 px) whose only section is `MAP` (`MapTab`, the generator form). `Esc` closes it.
- Right-click and `playerAnchor()` already convert to page coordinates with
  `canvas.getBoundingClientRect()`, so moving the canvas does not break menu anchoring.
- `ContextMenu` clamps to `window.innerWidth/innerHeight`, not to the viewport.
- The Phaser keyboard (WASD, `+`/`-`/`0`) and the window handlers in `App.tsx` (`Enter` focuses
  the input, `V` toggles the radial) listen globally; nothing gates them to a view.
- `web/tests/visual/spawn.spec.ts` shoots the canvas at 1280×720 and hides the HUD with
  `main > *:not(.world)` and `main.shell::after`.
- There is no LLM in the running game yet (VISION Phase 1 is "no LLM"). Dev-014's LLM lives in
  BitCanvas, not in the game client.

## 1. Decisions

| Topic | Decision | Why |
|---|---|---|
| Frame | The viewport is inset 20 px left, right and bottom; on top, 20 px plus a 28 px tab row | The frame the user asked for; the tab row is the "extra space" above it |
| Tab row | Tabs sit at the top-left, their left edge aligned with the viewport's left edge; the active tab joins the viewport border (no bottom line), inactive ones sit on the frame | Reads as folder tabs attached to the viewport |
| Right of the tab row | The dim `ETHERBOUND // LIVE SIMULATION` label moves there, right-aligned | Keeps the existing label without covering the frame's top edge |
| Tabs | `GAME`, `DEBUG`, `LLM`, in that order; the app always starts on `GAME` | User order; no persistence so a reload never lands on a tool view |
| Content | Each tab owns the whole framed area. `GAME` = canvas + HUD (unchanged placement, now anchored to the viewport). `DEBUG` and `LLM` = opaque panels that cover it | One view at a time; the HUD keeps its layout |
| Canvas while hidden | The Phaser game stays mounted and running; its wrapper gets `visibility: hidden`, never `display: none` | `Scale.RESIZE` would collapse to 0×0 and rebuild; the WebSocket, chunks and prediction keep flowing, so returning to `GAME` is instant |
| Clock | Switching tabs never pauses or changes speed | The server clock is authoritative and shared; pausing is an explicit act (`II`) |
| Input outside `GAME` | Leaving `GAME` closes the context menu, the radial and the `NEW` popover, blurs the input line, disables the Phaser keyboard and releases held keys; `Enter` and `V` do nothing outside `GAME` | Typing a seed in `DEBUG` must not walk Niko or open menus; a held `W` must not keep him walking |
| Keyboard | `Alt+1`/`Alt+2`/`Alt+3` select a tab from anywhere; ←/→ move between focused tabs (roving `tabindex`); `Esc` in `DEBUG` or `LLM` returns to `GAME` | STYLEGUIDE [Sec. 16]; `Esc` used to close the debug drawer, so it keeps meaning "back to the game". Alt+digit has no default binding in Edge/Chrome on Windows, and `MapScene` already ignores Alt |
| DEBUG view | `MapTab` moves as-is into the tab, inside a section strip (`MAP` only for now) and a content column capped at 480 px | Same form, room for future sections (physics, events) without another drawer |
| Debug drawer | `DebugDrawer`, the `DEBUG` pill button and the `debugOpen` state are removed. `.drawer` CSS stays for the future character/phone panels (STYLEGUIDE [Sec. 1] "Panels") | The tab replaces it; the drawer pattern is still the plan for Niko's panels |
| LLM view | A `.debug-placeholder` panel: `NO MODEL CONNECTED`, one line saying model calls and their logged events will appear here | Nothing to show yet; the tab reserves the place Phase 3 fills (VISION [Sec. 11], [Sec. 13]) |
| Minimum size | At 1280×720 the viewport is 1240×652 | Still above the STYLEGUIDE minimum; the HUD fits (checked against current panel sizes) |

## 2. Layout

```text
                20 px
      ┌──────┬───────┬─────┐                         ETHERBOUND // LIVE SIMULATION
      │ GAME │ DEBUG │ LLM │                                                     28 px
20 px ┌──────┘───────┴─────┴─────────────────────────────────────────────────────┐
      │ [clock + speeds]                                         [status pills]  │
      │                                                                          │
      │                              viewport                                    │ 20 px
      │ [event feed]                                                  [carry]    │
      │                                                               [meters]   │
      │ > input line                                                             │
      └──────────────────────────────────────────────────────────────────────────┘
                                         20 px
```

- `.shell` becomes a CSS grid: `grid-template-rows: 28px 1fr; padding: 20px`. Row 1 is
  `.view-tabs` (the strip plus the label), row 2 is `.viewport`.
- `.viewport` is `position: relative; overflow: hidden; isolation: isolate`. Its `1px solid
  var(--line-hi)` border and the cyan corner brackets that `.shell::before` drew (moved, same
  gradients) are a `.viewport::before` overlay at z 16, not a CSS border, so the canvas fills the
  whole 1240×652 box and the frame also shows over the `DEBUG`/`LLM` panels.
- Inside `.viewport`: `.world` and `.hud` at `inset: 0` (they were `inset: 8px` of the window),
  then `.view-panel` for `DEBUG`/`LLM` at `inset: 0; z-index: 15; background: var(--panel)`.
- The frame area (`.shell` padding) is `var(--bg)`, no content; it does not catch clicks meant for
  the world, and a click there closes menus as `.shell` does today.
- Menus (`.menu`, `.radial`) stay `position: fixed` at page coordinates. `ContextMenu` clamps to
  the viewport's bounding rect instead of the window.

## 3. Client

**web.ui** (new `viewTabs.ts`; `App.tsx`, `styles.css`)
- `viewTabs.ts` (pure): `VIEW_TABS = ["game", "debug", "llm"] as const`, `type ViewTab`,
  `tabLabel(tab)`, `tabFromHotkey(event: { key; code; altKey; ctrlKey; metaKey; shiftKey })`
  (returns the tab for `Alt+1..3`, matching `code` `Digit1..3` so keyboard layouts do not matter,
  `null` otherwise) and `stepTab(current, step)` (wraps).
- `App.tsx`:
  - `view` state (`"game"` at start) and a `viewRef` mirror for the window handlers.
  - `selectView(next)`: when leaving `game` it closes `menu`, `radial` and `newGameOpen`, blurs
    `inputRef`, and calls `sceneRef.current?.setKeyboardEnabled(false)`; entering `game` calls it
    with `true`.
  - The window `keydown` handler: `tabFromHotkey` first (preventDefault); `Esc` outside `game`
    calls `selectView("game")`; the `Enter` and `V` branches run only when `viewRef.current ===
    "game"`.
  - New `ViewTabs` component: `role="tablist"`, one `button role="tab"` per tab with
    `aria-selected`, `aria-controls` and roving `tabindex`; ←/→ call `stepTab` and move focus.
  - Markup: `.shell` > `ViewTabs` + `.viewport` > `.world` (`aria-hidden` and `.hidden-view` when
    not on `game`), `.hud` (same), `DebugView` / `LlmView` (`role="tabpanel"`, rendered only when
    active), then `ContextMenu` / `RadialMenu` as today.
  - `DebugView` wraps the current section strip (`.tabs`, `MAP`) and `MapTab`, which moves
    unchanged. Remove `DebugDrawer`, `debugOpen`, the `DEBUG` button and its `Esc` branch.
  - `LlmView`: the placeholder described in [Sec. 1].
  - `ContextMenu` clamps with the viewport rect (passed as a prop from a `viewportRef`).
- `styles.css`: `.shell` grid and padding; `.view-tabs`, `.view-tab` (active tab: `--panel`
  background, `--line-hi` border on three sides, cyan top rule, joins the viewport border by a
  1 px overlap), `.view-tabs .shell-label`; `.viewport` with the moved corner brackets; `.world`
  and `.hud` at `inset: 0`; `.hidden-view { visibility: hidden; }`; `.view-panel`; remove
  `.shell::before`/`::after`. Tab resets are written `button.view-tab::before` (and
  `button.tab::before` for the `MAP` strip): the bare class loses to the global
  `button:not(.mini)::before` brackets, which is why the old drawer tab showed `[ MAP ]`. The `@media (max-width: 700px)` block keeps working inside the
  viewport and reduces the frame padding to 8 px.

**web.game** (`MapScene.ts`)
- `setKeyboardEnabled(enabled: boolean)`: sets `this.input.keyboard.enabled` and, when disabling,
  calls `this.input.keyboard.resetKeys()` so a held WASD key is released and prediction stops.
  Nothing else in the scene changes.

No `server.*`, `web.net` or schema change.

## 4. What must not break

- Right-click and `V` menus open at the right place on the moved canvas, at x1, x2 and x4.
- WASD, zoom keys, `Enter`-to-input, right-click, the radial and the free-text line behave exactly
  as before while on `GAME`.
- The `MAP` form regenerates the world with the same request as before; switching back to `GAME`
  shows the new world without a reload.
- Leaving `GAME` while holding `W` stops Niko; typing digits or `W` in the `DEBUG` seed field
  neither moves him nor changes zoom.
- The clock keeps ticking (or stays paused) across tab switches.
- The Phaser canvas is never destroyed or resized to 0 by a tab switch.
- The `NEW` popover and its confirmation rules (STYLEGUIDE [Sec. 17]) are unchanged.

## 5. Acceptance

### Automated

1. `web/tests/view-tabs.test.ts`: `VIEW_TABS` order is `game`, `debug`, `llm`; `tabFromHotkey`
   maps `Alt+Digit1..3` and rejects plain digits, `Ctrl+Alt`, `Meta`, `Shift` and `Digit4`;
   `stepTab` wraps both ways.
2. `web/tests/visual/shell-layout.spec.ts` (Playwright, 1280×720, seed 7 with the clock running,
   since a paused clock already stops Niko and would hide a leaking key): the tablist has three
   tabs in order with `GAME` selected; the `.viewport` box is x 20, y 48, 1240×652 (±1 px); the
   canvas box equals it; holding `W` on `GAME` changes the `POS` readout (control); `Alt+2` selects
   `DEBUG`, shows the `MAP` form and keeps the canvas at the same size; holding `W` there leaves
   `POS` unchanged; `Esc` returns to `GAME`; `Alt+3` shows `NO MODEL CONNECTED`.
3. `web/tests/visual/spawn.spec.ts`: hide selector becomes `.viewport > *:not(.world)` and
   `.view-tabs`, plus `.viewport::before` (the frame overlay now sits on the canvas edges); x1/x2/x4
   baselines re-shot at the new 1240×652 canvas and approved by the user.
4. `npm run check` and `npm run check:visual`.

### Manual

5. Manual (GUI): the frame reads as a frame, the active tab joins the viewport, the HUD panels do
   not overlap at 1280×720, and right-click / `V` anchor on the right tile at x1 and x4. Reason:
   look and pointer feel need a screen.
6. Manual: `Alt+1..3` and ←/→ on a focused tab work in Edge; `Tab` order reaches the tabs before
   the HUD. Reason: browser focus and Alt handling need a real browser.

## TL;DR

The world viewport gets a 20 px frame and a folder-style tab row in its top-left corner: `GAME`
(world + HUD, unchanged), `DEBUG` (the map generator form, replacing the right-side drawer) and
`LLM` (a placeholder for the future model log). The canvas stays mounted and running behind the
other tabs, game keys are gated to `GAME`, `Alt+1..3` switch tabs and `Esc` returns to the game.
Client only: `web.ui` and a one-method `web.game` change; spawn baselines are re-shot and the
visual specs run on one worker.

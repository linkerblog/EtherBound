# Dev-002: Client Events and Frame Performance

[Architecture] [Host] [Rendering] [Performance]

Close the remaining host/client delivery and frame-time debts while preserving the rule that Godot
draws authoritative snapshots and never simulates. The accepted warm startup baseline remains 3.37 s;
this work targets host publication, actor update cost and chunk rebuild hitches, not engine load time.

## 1. Events to Godot

- [ ] Forward relevant, committed simulation events through the existing host response boundary in
      deterministic event order. Do not forward `clock.ticked` or events outside the player's
      observable actions/perception.
- [ ] Keep event delivery presentation-only: no Godot node may write sim state, infer outcomes or
      replace `WorldEngine` validation. Preserve the existing activity notice behavior without
      duplicate UI messages.
- [ ] Extend `HostRules.cs` for event order, filtering, request correlation and channel shutdown;
      verify the single-message event summary in `SimulationEventPresenterTests.cs`.

## 2. First published frame

- [ ] Profile host initialization, first `WorldFrame` publication and first-frame actor updates
      separately from executable startup.
- [ ] Preload immutable registry/catalog data in the Godot autoload before `WorldClient._Ready` and
      pass it into the host while SQLite restore proceeds on the simulation thread.
- [ ] Batch Extra actor draw instances while retaining per-actor interpolation state and keeping
      Niko as the individually followed node; this changes only presentation, never actor state.
- [ ] Reuse the render projection for unchanged immutable host chunks and reuse existing band mesh
      nodes when their chunk key survives a revision.
- [ ] Keep the accepted 3.37 s warm-launch baseline. Reduce host time from `_Ready` to its first
      complete frame to at most 50 ms without hiding world content or moving simulation state into
      Godot. First-frame actor updates have the separate 20 ms budget.
- [ ] Add stable diagnostics/bench coverage for timings; record a windowed manual run because
      headless Godot does not render.

## 3. Chunk rebuild hitch

- [ ] Measure a natural border crossing against the same chunk count and scene conditions as the
      baseline; keep the serial and parallel vertex data byte-identical.
- [ ] Reduce main-thread mesh/node creation below the 40 ms transition budget without hiding or
      dropping world content. Keep `ArrayMesh`, material and node work on Godot's main thread.
- [ ] Add repeatable geometry parity coverage and a windowed trace for natural chunk transitions.

## 4. Boundaries and records

- `SimulationHost` stays the sole owner of the simulation thread and host response channel.
- Godot receives immutable event data and snapshots; it never resolves game rules.
- Preserve deterministic event ordering and the current worker/main-thread resource boundary.
- Update `docs/excalidraw/system-map.excalidraw` for the event path if it changes.
- Bump each touched `sim.*` or `game.*` module by `0.0.1`, update durable guidance, Notion and
  `docs/PENDING.md`.

## 5. Acceptance

- Host tests cover committed event order, player visibility and shutdown without losing notices.
- First-frame host latency and actor-update time are separately measured on windowed runs; startup
  baseline remains accepted at 3.37 s median over five warm launches.
- A natural chunk border crossing meets the 40 ms budget and produces identical serial/parallel
  geometry without missing content.
- `npm run check` passes.

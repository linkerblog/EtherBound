# Dev-001: Skeleton (Phase 0)

[Infrastructure] [Tooling] [Networking]

The first code of EtherBound. It builds the pipes, not the game: a FastAPI server with a running
clock, a Phaser client where Niko walks with WASD, a database with real migrations, and generated
types between both sides. No world model, no NPCs, no LLM. Everything later plugs into this.

Design reference: `VISION.md` [Sec. 3], [Sec. 4] and [Sec. 15] Phase 0.

## 3. What gets built

### 3.1 Clock (`server/clock.py`)
- Asyncio task; one tick = one game minute. Default 1 real s = 1 game min, configurable.
- Speeds x1, x3, x10 shorten the tick interval; pause stops it.
- **Autopause lock:** a counter any system can take and release (scenes will use it in Phase 3).
  The clock runs only with zero locks and not paused.
- Game time is persisted every tick batch, so a restart resumes where it stopped.
- No wall-clock reads anywhere else in the simulation: the clock is the only source of time.

### 3.2 Action API and world engine (`server/engine/`)
- `submit(actor_id, action)` is the single entry point that mutates state, from day one.
- Phase 0 verb: `move(direction)`. The player's WASD input becomes this action; later every actor
  uses the same door.
- Movement is continuous in metres (float x, y; integer z = 0 for now) at walking speed, with
  collision against wall tiles of the test map.

### 3.3 Networking (`server/net/`, `web/src/net/`)
- REST: `GET /api/health`, `POST /api/game/new {seed}`, `GET /api/game/state`,
  `GET /api/menu?x&y&z`.
- WebSocket `/ws`:
  - server → client: `snapshot` (on connect), `tick` (clock + actor positions), `ack` (last input
    sequence processed).
  - client → server: `input` (WASD vector + sequence number), `clock` (pause, speed).
- **Prediction:** the client moves Niko immediately, keeps unacknowledged inputs, and on each `ack`
  rewinds to the server position and replays pending inputs. Movement code is small and mirrored
  on the client; the server always wins.
- Movement runs at its own rate (about 20 Hz), independent of the 1 Hz game clock, and keeps
  running while paused only if the design says so. **Default: pause freezes Niko too.**

### 3.4 Types (`server/net/schema.py`)
- WS messages are not part of OpenAPI, so `schema.py` adds them to the OpenAPI components and
  writes `schema.json`. `npm run gen:types` turns it into `web/src/net/schema.d.ts`.
- The generated file is committed; the check step fails if regenerating it produces a diff.

### 3.5 Database (`server/db/`, `alembic/`)
- `data/etherbound.db`. First migration creates:
  - `world_meta`: seed, game minute, speed, paused.
  - `actor`: id, kind (`player` for now), x, y, z.
- `POST /api/game/new` wipes game rows and seeds them through the ORM; the schema itself only
  changes through migrations.
- Migrations run on server start (`alembic upgrade head`).

### 3.6 Client (`web/`)
- Top-down camera following Niko. Placeholder art: coloured squares, 1 tile = 1 m. LimeZu assets
  come in Phase 1 with the real world model.
- WASD movement with prediction.
- **Right-click:** asks `/api/menu` for the tile and shows the returned verbs. Phase 0 returns
  `inspect` only; the point is that the menu comes from the server, never from the client.
- **Enter:** opens a free-text box. Phase 0 only echoes the text in the overlay.
- Overlay shows game time, pause and speed buttons.
- The overlay follows `docs/STYLEGUIDE.md`: layers [Sec. 1], fonts, palette, base, HUD panels,
  clock [Sec. 6], buttons, context menu [Sec. 8] and input line [Sec. 9]. Diegetic effects
  [Sec. 15] arrive with the systems that trigger them.

### 3.7 Determinism groundwork
- `rng.py` with a seeded stream per named system, derived from the world seed. Nothing uses it yet
  except a test; bare `random` is banned by a ruff rule.

### 3.8 Dev tooling (`scripts/`)
- `npm run dev` (from root) starts server and client together; `npm run stop` kills both, including
  orphaned processes holding the database file (Windows).

## 5. What must not break

Nothing exists yet, so this phase sets the rules the rest inherits:

- The world engine is the only writer of state; routes and the WS hub call `submit`, never the
  database directly.
- The player moves through the action API, not a private path.
- The clock is the only source of game time.
- Schema changes go through Alembic.
- TypeScript types are generated, never hand-written.
- No bare `random`.

## TL;DR

Phase 0 builds the pipes: FastAPI + a persistent 1 Hz clock with pause and speeds, a Phaser client
where Niko walks with WASD using client prediction, SQLite with Alembic from the first table, types
generated from Pydantic, and a server-generated right-click menu stub. Movement already goes
through the single action API. Ten modules land on v0.0.1. No game content yet.

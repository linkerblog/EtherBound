# Dev-008: LLM roles and the narrator

[Feature] [LLM] [Host] [UI]

Dev-007 lets the player type and have Niko act; the only feedback is the engine's plain line.
This plan adds the second half of the playable loop: an OpenRouter client with per-role config and
a **narrator** that turns what Niko just did and perceived into two or three short sentences in the
feed, streamed as they are written. The narrator proposes text only. It never writes state, never
sees what Niko could not perceive, and a failed call falls back to the engine's line, so the game
never waits on a model.

## 1. Findings

Read from the source and from NikoStory; nothing here was run.

- **The feed already receives the right facts.** `HostActionResponse.Events` carries the ordered
  committed player events of an action, and `HostEventsResponse` carries asynchronous ones;
  replication already excludes `clock.ticked` and events outside Niko's observable actions or
  perception. The narrator can read exactly that and nothing more.
- **The LLM tab is a placeholder** (`GameHud.cs`, `_llmView`), kept for this work (Dev-004).
- **NikoStory measured four lessons** (`AGENTS.md` and `VISION.md` [Sec. 13] carry them): never pass
  `reasoning` to a model that does not reason (3x slower for no gain); use an idle timeout that
  resets on every streamed chunk, never a total timeout; reject a narration that repeats the last
  one or states distances in tiles; keep prose models out of state.
- **NikoStory's author format** (`docs/inspiration.txt`): "Short sentences with clear intention,
  small worldbuilding, fast paced, no decorative text", Niko literal, calm, introverted. VISION
  [Sec. 8] lists the same traits.
- **No store exists for LLM calls.** The `event` table logs decisions, but prose and token cost
  need their own table; `docs/PENDING.md` already tracks unbounded `event` growth, so this plan
  must not add to it carelessly.

## 2. Decisions

Marked **approval needed** where the choice is open.

- **D1. OpenRouter client in `sim.llm`.** `IChatModel.Stream(request, ct)` yields text deltas;
  `OpenRouterChat` is the HTTP implementation (SSE over `chat/completions`, `HttpClient`
  injected), `ScriptedChat` serves tests. Same module and same dependency rule as Dev-007: the
  sim never references it.
- **D2. Roles are data.** `Data/llm.toml` gains a `[roles.narrator]` table: model, `reasoning`
  (default `false`), `idle_ms` (default 20 000), `max_tokens`. A role registry is the only place a
  role is declared, so the later `agent` role of Phase 3 is one more table. Overrides from the LLM
  tab are saved in `llm.json` in the user data dir (an install preference: a new game keeps them),
  resolved as tab, then environment (`ETHERBOUND_NARRATOR_MODEL`), then data default. The key is
  `OPENROUTER_API_KEY` (environment or `llm.json`) and is never readable from the UI. **Amended by
  `Dev-009.md`:** it is no longer "never editable": the tab has a masked, write-only box that saves it to `llm.json`.
- **D3. Narrator input is a witnessed packet.** `NarrationPacket` is built from: the committed
  events of the action (type, subject, target label, outcome), Niko's tile and what `inspect`
  already returns for it (object and actor labels within sight), the time-of-day word from the
  clock (no digits), Niko's four traits, and the last three narrations. It contains no coordinates,
  ids or hidden container contents. A test asserts the packet text has none of those.
- **D4. What is narrated.** Every accepted action except `move` and `wait` of under a minute, plus
  `inspect`, plus the confirm and reject lines of Dev-007 in the engine's own words. Walking is not
  narrated. At most one narration in flight; events that arrive meanwhile are merged into the
  next one. Provisional, in `Data/llm.toml`.
- **D5. Cheap deterministic checks, one retry, then the engine line.** Reject: empty, over
  `max_chars` (400), equal to one of the last three, or containing a number followed by a length
  unit (`m`, `metres`, `tiles`). One retry with the failure named in the prompt; on a second
  failure the feed shows the engine's plain text and the call is recorded as `rejected`. No
  continuity rewrite pass: NikoStory's second model call is not worth its cost before there is
  enough story to contradict.
- **D6. Spend cap and call log.** Migration `0011_llm_call` adds `llm_call(id, game_minute, role,
  model, tokens_in, tokens_out, cost_usd, outcome, error, prompt, response)`. Cost is the value
  OpenRouter returns, `NULL` when absent. `spend_cap_usd` (default 1.00, provisional) stops the
  narrator for the session when reached; the feed says so once and free text keeps working through
  Jev. The table is a debugging and billing log, not gameplay state: replay ignores it.
  **Approval needed:** keep full prompt and response text, or only the first 500 characters of
  each. Recommended: full text for the last 200 rows and truncated beyond, pruned on startup,
  because it must not grow without bound while the retention item is open.
- **D7. Narration is committed as an event.** After a narration passes the checks, the host asks
  the engine to commit `llm.narrated {text, from_seq, to_seq}` through `RecordDecision`
  (Dev-007 D8). The feed can then rebuild the last 30 lines after a restart, and the log reads as
  a story. **Approval needed:** if refused, the story is lost on restart and the event log stays
  smaller.
- **D8. The LLM tab becomes real.** Rows per role: model (autocomplete is out of scope, a text
  box), reasoning toggle, idle timeout, key state, session cost and calls, last five calls with
  outcome. Edits apply to the next call with no restart.
- **D9. Prompt is a data file.** `Data/prompts/narrator.md`, embedded, English, holding the format
  rules of `docs/inspiration.txt` and "propose text only, state nothing the packet does not say".
  A prompt change is a data change and bumps `sim.llm`.

## 4. Bench

`dotnet run --project sim/EtherBound.Llm.Bench -- narrator` replays a recorded 20-action session
through two or three candidate models and prints p50/p95 time to first token, total time, cost per
narration and the rejection rate of D5. Pass rule, written before the numbers: **p95 first token
under 2.5 s and fewer than 10 % rejected after the retry.** The default model in `Data/llm.toml` is
the cheapest candidate that passes; no model is named in this plan because none was measured.

## 5. What must not break

- The world engine is the only writer. The narrator reads events and proposes text; the only
  write is `RecordDecision`, validated by kind.
- Reactions come from knowledge: the packet holds only what Niko perceived (the same filter as
  event replication).
- `reasoning` is `false` by default and passed only when a role sets it.
- No spend over `spend_cap_usd`; with no key or an exhausted cap the game plays exactly as after
  Dev-007.
- The sim thread never waits on a model; WASD, menus and the clock are unaffected by a pending
  narration.
- Replay and the input journal do not depend on narration or on `llm_call`.
- The key never reaches a frame, event, log line, prompt log or the UI.

Findings. `deepseek-v4-flash` reasons by default, so `REASONING` off still thinks: with the old `max_tokens = 300`
four narrations in twenty came back empty because the thinking ate the budget, and one stopped mid-word; disabling
its reasoning from the request made it fast but it ignored the prompt and invented scenes. `max_tokens` is now 1000
and a `length` finish is named ("the model spent its whole token budget") and never shown cut off. Prose differs
more than the rule can see: Mistral is the best written but invents small details (a pigeon, a latch), while
`gpt-4.1-nano` obeys "never invent" but repeats "Niko stands on the asphalt". The player chose
Gemma, and the default in `Data/llm.toml` is `google/gemma-4-31b-it`: of the Gemma models it had the fastest p95 first
token (0.57 s), no rejections and no invented details, at $0.000027 a narration. Its prose is faithful and terse, with
a repeated closing line ("He stands on the asphalt beside a shovel and a chest"); `gemma-4-26b-a4b-it` is cheaper
still ($0.000019). A model chosen in the LLM tab still beats the default.

## TL;DR

An OpenRouter client and a narrator in `sim.llm` turn the events Niko witnessed into two or three
short streamed sentences. Roles, models and the spend cap are data with a real LLM tab, `reasoning`
is off unless set, every call is logged in a new `llm_call` table, and each narration is committed
as `llm.narrated` so the story survives restarts. Checks, one retry and the engine's plain line mean
a model failure never blocks play, and a bench with a written pass rule picks the default model.

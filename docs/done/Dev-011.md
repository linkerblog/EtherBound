# Dev-011: Roofing and brick wall textures (BitCanvas + game)

[Art pipeline] [Tooling] [Rendering]

On 23/09/2026 the user's screenshot on the test building's roof (Niko at `Z 4 (12.0 m)`) showed
two flat materials among textured ones: the roof slab (`roofing`, `#4d5058`, the z=4 floor in
`world/gen/testworld.py`) and the brick walls (`brick`, `#a6533d`). Roofing is a floor material
and only lacks sheets, as asphalt did in `docs/done/Dev-010.md`. Walls are drawn by a separate path
(`MapScene.drawWall`, flat `wallN/W` masks of 4/2/1 units) that never reads a sheet. This doc adds
both materials to BitCanvas and teaches the wall path to draw any material that has a side sheet.

Reference: `docs/done/Dev-010.md` (how a BitCanvas material is added, tone calibration, hash
check); `docs/done/Fix09.md` (side sheet contract, `shearSideCell`, one unit per cell, cap only on
the real top); `docs/done/Dev-009.md` [Sec. 3.3], [Sec. 3.4]; `CONTEXT.md` (web.game, BitCanvas
pitfall).

## 1. Decisions to approve

| Topic | Decision | Why |
|---|---|---|
| Roofing look | Flat-roof bitumen membrane: dark grey, soft broad noise, one overlapped roll seam per tile, sparse grit. The seam is drawn only on the top, not on the slab's side faces | The roof here is a flat slab (a floor at z=4), not a pitched roof, so shingles would read wrong. A seam on a side face would become a diagonal streak |
| Brick look | Running bond: courses of 4 px (3 brick + 1 mortar), bricks 8 px long (7 + 1 mortar), odd courses offset 4 px; per-brick tone variation; light mortar. The wall's top unit (cap) carries a header course (4 px bricks) | Readable at x1; 4 courses per 16 px unit and 4 bricks per 32 px cell keep every unit and every cell seamless |
| Brick top | Running-bond pavers on the diamond, for BitCanvas's two-sheet contract and for any future brick floor | Every BitCanvas material exports both sheets; the game ignores the top unless a brick floor exists |
| Files | `floor/roofing_x4.png`, `floor/roofing_side_x4.png`, `wall/brick_x4.png`, `wall/brick_side_x4.png` | `floor/` holds walkable surfaces; `wall/` is new and says what brick is for. `gamesync.js` creates missing folders already |
| Walls in the game | A wall of any material with a side sheet is drawn textured, one unit per cell, cap on the wall's real top unit, fill below. Materials without a sheet keep today's flat masks | Generated, not authored (AGENTS.md): concrete or wood walls get textures for free, no brick special case |
| Wall cells | Built from the same 128×32 side sheet by a new `shearWallCell`, the mirror of `shearSideCell` over `wallMask`'s contour | One sheet per material, one contract. The wall N footprint has the same slope as face S, the wall W footprint as face E |
| Wall light | Tint `0xffffff` scaled by the existing wall light (N 0.82, W 0.66). No height shading, as today | Keeps walls exactly as bright as the flat walls they replace, relative to their colour |
| Windows, wall top line | Unchanged: the glass band stays a flat `0xd8e6f0` at 0.45 alpha and the 1 px top line stays flat | Glass is not brick; the line is the wall's top face, 1 px tall |
| Atlas | Wall cells go in their own band below the side band, with the same 4096 px width limit | Side cells use 512 px per material; after this doc there are 6 side sheets (3072 px). Wall cells in the same band would reach 6144 px |
| Tone | The default sheets' mean colour matches the material colour (`#4d5058`, `#a6533d`) within about 5 per channel, tuned by the base level, as in Dev-010 | The textured surface must not look lighter or darker than the flat one it replaces |

## 2. What changes

### 2.1 `bitcanvas` (v0.0.2 → v0.0.3)

`BitCanvas/app.js`:

- `materialPalettes.roofing` and `materialPalettes.brick` [Sec. 2.2].
- `GAME_SHEETS.roofing = { folder: 'floor', variants: 'roofing_x4.png', sides: 'roofing_side_x4.png' }`,
  `GAME_SHEETS.brick = { folder: 'wall', variants: 'brick_x4.png', sides: 'brick_side_x4.png' }`.
- `materialLevel(material, x, y, seed, brightness, face = false)`: new optional last argument,
  ignored by every existing branch (their output must stay byte-identical). `createSideCell`'s
  generic branch passes `true`; `createMaterialTile` passes nothing. Two new branches **before**
  the final cobblestone `else`:

  ```js
  } else if (material === 'roofing') {
    // v has period 2 per tile; the seam runs through the centre line (v = 0), off the tile edges.
    const roll = (((v + 1) % 2) + 2) % 2;
    const broad = isoNoise(x + 0.5, y + 0.5, 4, 4, seed);
    const fine = isoNoise(x + 0.5, y + 0.5, 15, 15, seed ^ 0x2545f491);
    const grit = materialCellHash(x, y, seed ^ 0x6c8e9cf5) % 100;
    level = 3.2 + (broad - 0.5) * 0.7 + (fine - 0.5) * 0.4 + brightness;
    if (!face && roll >= 1 && roll < 1.06) level -= 1.3;       // seam shadow
    else if (!face && roll >= 1.06 && roll < 1.16) level += 0.7; // overlapped lip
    if (grit < 5) level += 1.2;
    else if (grit < 8) level -= 0.8;
  } else if (material === 'brick') {
    // Pavers: 4 courses across v, 2 bricks along u, odd courses offset half a brick.
    const course = Math.floor((v + 1) * 2);
    const across = (v + 1) * 2 - course;
    const along = ((u + (course % 2) * 0.5) % 1 + 1) % 1;
    const tone = materialCellHash(Math.floor(u + (course % 2) * 0.5) & 1, course & 3, seed) % 5;
    level = 3 + (tone - 2) * 0.35 + (isoNoise(x + 0.5, y + 0.5, 13, 13, seed) - 0.5) * 0.6 + brightness;
    if (across < 0.06 || along < 0.03) level = 6.2 + brightness * 0.25;
  }
  ```

  The constants are starting points: the implementer tunes thresholds until the mortar reads as a
  1 px line, and the base levels for tone [Sec. 1]. Record the final values here.

  **Final tuned constants (23/09/2026).** Roofing base level `3.9` (was `3.2`): the default top
  sheet's mean is exactly `(77, 80, 88)` = `#4d5058`. Brick pavers base level `3.9` (was `3`): the
  default top sheet's mean is `(168, 87, 65)`, within 4 per channel of `#a6533d`. The mortar level
  `6.2`, the mortar tests (`inCourse === 3`, `inBrick === step - 1`), the header course, the
  patterned straddling brick and `brickSideColor`'s base `3` are unchanged from the plan. The
  brick side sheet's mean is `(165, 90, 68)`, lighter than the body colour as expected from its
  ~34% light mortar.
- `createSideCell`: a new `material === 'brick'` branch next to planks, calling a new
  `brickSideColor(colors, x, faceRow, seed, patternSeed, part, brightness)`:
  - `course = Math.floor(faceRow / 4)`, `inCourse = faceRow % 4`, `offset = (course % 2) * 4`,
    `brick = Math.floor((x + offset) / 8)`, `inBrick = (x + offset) % 8`.
  - Mortar when `inCourse === 3` or `inBrick === 7`: level `6.2 + brightness * 0.25`.
  - Cap part, `faceRow` 0–3: header course, `inBrick` computed with a 4 px period instead of 8,
    and row 0 raised by +0.8 (the lit top edge).
  - Brick body: tone `materialCellHash(brick & 3, course, s) % 5`, where `s` is `patternSeed` for
    the brick that straddles the cell edge (`brick % 4 === 0` on odd courses) and the variant
    `seed` otherwise, so the two halves of a straddling brick match whichever variants meet.
    Level `3 + (tone - 2) * 0.35 + small isoNoise speckle + brightness`; the brick's top row
    (`inCourse === 0`) +0.4.
  - Every course pattern repeats every 16 rows (4 courses, an even count), so cap over fill and
    fill over fill line up.
- `createSideCell` generic branch: pass `face = true` to `materialLevel` (roofing uses it).
- `updateMaterialControls` `materials` table:
  - `roofing: { title: 'Roofing texture', subtitle: 'Flat roof membrane', corner: 'ROOF DECK', description: 'Bitumen membrane with overlapped roll seams and fine grit.' }`
  - `brick: { title: 'Brick texture', subtitle: 'Running bond', corner: 'BRICK WALL', description: 'Fired bricks in running bond with light mortar and a header course.' }`
- `randomMaterialPalette`: roofing hue `[200, 230]`, saturation `[3, 12]`, lightness span
  `[10, 50]`; brick hue `[5, 25]`, saturation `[40, 65]`, default lightness span. Others unchanged.

`BitCanvas/index.html`: two rows after Asphalt, same markup as their neighbours:
`roofing-material` (icon `▱`, `<b>Roofing</b>`, `floor/roofing_x4`) and `brick-material`
(icon `▥`, `<b>Brick</b>`, `wall/brick_x4`).

### 2.4 `web.game` (v0.1.8 → v0.1.9)

- `terrainSprites.ts` / `terrainSheets.ts`: `roofing` → `floor/roofing_*`, `brick` →
  `wall/brick_*`, in both tables, with static imports (the test checks all three).
- `terrainSprites.ts`: `sideVariant(x, y, side, h)` accepts `"s" | "e" | "n" | "w"`; `n` and `w`
  xor their own constants (`0x7f4a7c15`, `0x94d049bb`). `s` and `e` outputs stay identical.
- `tileMasks.ts`: `shearWallCell(sheet, edge: "n" | "w", part, variant): SideCell`. Same as
  `shearSideCell`, but over `wallMask(edge, 1)`: columns `n` 32–63, `w` 0–31; each column takes its
  whole 16-pixel sheet column (`variant * 32 + column`, cap row 0 or fill row 16) and places it at
  `topRow(x) - 16 … topRow(x) - 1`.
- `MapScene.createTerrainAtlas`: for every loaded side sheet, also build the 16 wall cells
  `wall:<key>:<n|w>:<cap|fill>:<v>` into a wall band at `y = 160 + sideHeight`, with its own
  4096 px width guard (warn and skip, like the side band). Canvas height grows by the band's
  height. Track loaded keys in a `wallKeys` set.
- `MapScene.drawWall`: if the wall material's key is in `wallKeys`, replace each flat
  `drawWallRun` with `drawWallUnits(edge, …, bottom, top, key, light)`: one cell per unit from
  `bottom + 1` to `top`, part `cap` only when `!stub && unitTop === base + MAX_WALL_H` (the wall's
  real top, not a cutoff or a stub), `fill` otherwise; variant `sideVariant(x, y, edge, unitTop)`;
  tint `scaleColor(0xffffff, light)`. The window's lower (base → base+2) and upper
  (base+4 → top) runs are textured the same way; the glass run and the top line stay as they are.
  Materials without a sheet keep the current code path unchanged.

## 4. Acceptance

## TL;DR

Adds Roofing (flat bitumen membrane with roll seams) and Brick (running bond with a header course)
to BitCanvas and generates their sheets. The game textures the roof like any floor, and draws walls
of any material with a side sheet one unit at a time from a new `shearWallCell`, in their own atlas
band, with a cap on the real top. Windows, stubs and flat walls without sheets are unchanged.
`bitcanvas` v0.0.3, `web.game` v0.1.9, project v0.6.7.

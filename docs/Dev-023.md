# Dev-023: Server kernel — systems as modules

[Refactor] [Architecture] [Engine] [Events]

The architecture in `docs/utils/VISION.md` [Sec. 4] is already framework-grade: one writer, one
action API, systems that only meet on the bus. The code does not yet make the right move the easy
one. Wiring is manual and centralized, dispatch order depends on line order in `app.py`, the core
names specific ops, and two packages import upward. Six primitives are still to come
[Sec. 6 of VISION], and each one would widen `WorldEngine` and `app.py`. This doc turns the
existing seams into explicit extension points, with **no behaviour change**: same events, same
order, same schema. It is the first of the kernel docs [Sec. 8].

**Precondition:** `Fix14` is committed and the working tree is clean. `Dev-021`, `Dev-016` and
`Dev-014` have not started their server parts [Sec. 1, Order].

## 1. Decisions

| Topic | Decision | Why |
|---|---|---|
| Behaviour | Pure refactor. The event log of a scripted run is byte-identical before and after; `schema.d.ts` regenerates byte-identical | The tests and the log are the proof; a logic change would weaken both |
| Phases | The bus dispatches by **phase**, then by subscription order within a phase: `CORE` (0), `MINDS` (1), `SYSTEMS` (2), `REPLICATION` (3), `AUDIT` (4). `subscribe(..., phase=Phase.SYSTEMS)` is the default | Order becomes a declared fact. Today's order maps exactly: clock sync `CORE`, Extras `MINDS`, hub `REPLICATION`, log `AUDIT` |
| Systems | A `System` protocol in `events/system.py`: `name: str` and `attach(bus: EventBus) -> None`. `app.py` builds a `systems` tuple and attaches each one | A new system is one entry in one tuple; the bus stays the only meeting point |
| Op packs | Each handler file exports `HANDLERS: tuple[OpHandler, ...]`. `ops/__init__.py` registers the packs; `register` keeps its current checks | The list lives next to the handlers it names. Registration order does not matter: `handled_ops()` follows catalog order |
| `BaseOp` | New class in `ops/base.py` with defaults: `subject → None`, `duration → 0`, `complete → []`, `changes_load = False`. Handlers inherit it and delete their trivial copies. `OpHandler` stays the typing protocol | Removes F5 boilerplate; a later method such as Dev-016's `detail` gets its default in one place |
| Load refresh | `OpHandler.changes_load: ClassVar[bool]`. True for `take`, `drop`, `put`, `open`, `close`, `wear`, `remove`, `throw` (today's exact set). `submit` asks the handler | The core stops naming ops (F3) |
| `Action` union | Stays a static union in `engine/actions.py`. A check at the end of `ops/__init__.py` fails the import when a handled op has no union member, a union member has no handler, or a member's `op` literal is not in the catalog | Pyright and the OpenAPI schema need a static union; building it at runtime would lose both. The check makes a missed step loud |
| Core types | New package `etherbound/core/` (module `server.core`), `types.py`: `PLAYER_ID`, the five targets and `Target`, the four locations and `Location`, `Spot`, `PhysicsPosition`, `TilePos`. No re-exports from the old paths | Leaf value types every layer shares. One import path per symbol (the Dev-022 rule) |
| `EnginePort` | Protocol in `engine/port.py` with the ten members of F9 plus `menu`. `minds` and `net` type against it | Jev and LLM brains will implement against the same surface; tests can pass a fake |
| Layers | `test_architecture.py` gains an import table: `core` → nothing; `world` → `core`, `rng`; `events` → `core`; `engine` → `core`, `world`, `events`, `db`, `rng`; `minds`, `net`, `routes` → the above minus `db`, and never `engine.world`; only `app.py` and `cli.py` import everything | F7, F8 and F10 cannot return |
| Schema CLI | `main` moves from `net/schema.py` to `etherbound/cli.py` (`server.app`); `pyproject.toml` script becomes `etherbound.cli:schema` | Breaks the `net → app` cycle; the command name is unchanged |
| Order | Lands before `Dev-021`, `Dev-016` and `Dev-014` start their server parts; their pointers are rewritten [Sec. 3.7] | All three edit `ops/base.py`, `actions.py` or `app.py`; they should land on the kernel |

## 2. Out of scope

- Components for the new primitives, perception, typed event payloads and the web kernel. Each is
  its own doc [Sec. 8].
- Performance: `ActionContext.others_on` scanning every actor, `get_state()` per brain tick.
  Tracked in `docs/PENDING.md`.
- `handling.py` split, renames of public engine methods, the WebSocket and REST contracts.

## 3. What changes

### 3.1 server.core (new, `server/src/etherbound/core/`)

- `__init__.py`, `types.py` with the symbols of [Sec. 1, Core types], moved unchanged from
  `engine/actions.py` and `events/models.py` (`TilePos`).
- Importers switch paths: 13 files in `src` and `tests` import these from `engine.actions`, plus
  the `TilePos` importers. `engine/world.py` drops its `PLAYER_ID = actions.PLAYER_ID` alias;
  `net/ws.py` imports `PLAYER_ID` from `core.types`.

### 3.2 server.events

- `bus.py`: `Phase` (`IntEnum`, [Sec. 1, Phases]); `subscribe(event_type, handler, *, name,
  phase=Phase.SYSTEMS)` inserts after the last handler of the same or a lower phase. `drain`,
  the cascade cap and failure isolation are untouched.
- `system.py`: the `System` protocol.
- `models.py`: imports from `core.types` only.

### 3.3 server.engine

- `ops/base.py`: `BaseOp`; `changes_load` on `OpHandler`.
- Every handler file: inherit `BaseOp`, delete methods equal to its defaults, export `HANDLERS`.
  `PhysicsHandler` keeps its `op_name` constructor; `ThrowHandler` sets `changes_load = True`.
- `ops/__init__.py`: register the seven packs (`move`, `climb`, `wait`, `inspect`, `dig`,
  `handling`, `physics`), then the union check [Sec. 1, `Action` union].
- `port.py`: `EnginePort`.
- `world.py`: delete `HANDLING_OPS`; `if handler.changes_load:`; a private
  `_result(session, actor, action, *, accepted, **fields)` replaces the four `ActionResult`
  constructions. Signatures of public methods unchanged.

### 3.4 server.minds

- `ExtrasBrain(engine: EnginePort, ...)`; `subscribe(bus)` becomes `attach(bus)`, `name =
  "minds.extras"`, `phase=Phase.MINDS`.

### 3.5 server.net

- `WebSocketHub(engine: EnginePort)`; new `attach(bus)` subscribes its five handlers at
  `Phase.REPLICATION` under today's names (`websocket.clock_ticked`, …).
- `schema.py` keeps `combined_schema` and `export_schema`; `main` leaves [Sec. 3.6].

### 3.6 server.app

- `app.py`: two small systems defined in place, `ClockSync` (`CORE`, the `ClockChanged` lambda
  today) and `EventLog` (`AUDIT`, `log_event`). `create_app` builds
  `systems = (ClockSync(clock), ExtrasBrain(...), hub, EventLog())` and attaches each. The
  "extras before hub" comment goes; the phases say it.
- `cli.py`: `schema()`, the old `net.schema.main`.

### 3.7 Docs and tooling

- `pyproject.toml` script path [Sec. 1, Schema CLI].
- `docs/utils/VISION.md` [Sec. 4], one bullet after "Systems never call each other": *A system is
  a module that attaches to the bus in a named phase; ops come in packs; the core never names a
  specific op.*
- `CONTEXT.md`: module row `server.core`; the Event bus contract states phases; the Ops contract
  names `BaseOp`, packs, `changes_load` and the union check; the Minds contract says `EnginePort`.
  A new pitfall: *adding an op is `ops.toml` + union member + handler in a pack; the import check
  names the missing one.*
- Open docs, file + symbol pointers only: `Dev-016.md` (`detail` default goes on `BaseOp`),
  `Dev-014.md` (its services attach as a `System` or live on `app.state`, never a bare
  `bus.subscribe` in `create_app`), `Dev-021.md` (`EdgeTarget` lives in `core/types.py`).
- If `Infra02` is mid-edit on `CONTEXT.md`, whichever lands second merges the other's text.
- `docs/PENDING.md`: the two performance items of [Sec. 2] and the follow-up docs of [Sec. 8].

## 5. What must not break

- The engine stays the only writer; nothing outside `engine/` and `db/` touches the session.
- Dispatch order for every event type equals today's [Sec. 1, Phases].
- `register` still refuses a key missing from `ops.toml` and a duplicate (`test_ops.py`,
  `test_events.py`).
- Menus: same entries, same order, same `available`/`reason` on every existing test tile.
- `schema.d.ts`, the WebSocket messages and the REST responses are byte-identical.
- The Extras replay: same seed and inputs give the same `actor.goal_set` and `actor.moved` rows.

## 8. The kernel docs that follow

Written one at a time, each after the previous lands. Listed here so the order is agreed.

| Doc | What | Open decision |
|---|---|---|
| Components | Typed per-actor and per-object data that a system registers (needs, traits, relationships, knowledge), so a primitive never adds a column to `actor` nor a field to `WorldEngine` | **Storage, for the user:** one generic component table (a new primitive needs no migration, but SQL cannot query inside it), a table per primitive (queryable, one migration each), or hybrid. Recommended: hybrid, own tables for knowledge and relationships, generic for the rest |
| Perception | The engine computes who perceived each event; minds subscribe to perceived events, never to the raw log | Pillar 3 depends on it; it must be a kernel piece before witnesses exist, or each system filters its own way |
| Typed events | Replace the `dict[str, Any]` fields (`target`, `changes`, `damage`, `broken`, `goal`) with models, keeping the stored JSON readable | Whether old log rows are migrated or read through a compatibility parser |
| Web kernel | A `SceneLayer` interface for `ChunkRenderer`, `ExtrasLayer`, `PhysicsAnimator`; message dispatch by type in `client.ts`; HUD panels as a list | None yet |

## TL;DR

- Pure refactor: same event log, same dispatch order, same schema; no migration.
- The bus dispatches by named phase; systems attach from one tuple in `app.py`.
- Ops come in per-file packs on a `BaseOp` with defaults; `changes_load` replaces the core's op
  list; an import-time check keeps `ops.toml`, the `Action` union and the handlers aligned.
- New `server.core` holds shared value types; `EnginePort` is what minds and the hub see; an
  import-layer test forbids upward imports and the `net → app` cycle.
- Components, perception, typed events and a web kernel follow as their own docs; the component
  storage choice is the user's.

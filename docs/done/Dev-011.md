# Dev-011: Needs and utility for Extras

[Feature] [Minds] [Engine] [World] [Migration]

An Extra today only wanders (`ExtrasBrain`: a `wander` goal within 12 m of its anchor, or `wait`).
Nothing it does has a reason. This plan adds the first half of the Phase 2 line "Needs, utility with
trait weights" (`docs/utils/ROADMAP.md` [Sec. 15]): three needs (hunger, thirst, rest) that decay with
game time, three ops that satisfy them (`eat`, `drink`, `sleep`) on the same action API Niko uses, and a
utility step in the Extras' brain that picks among what the engine itself offers. Traits, organizations,
tasks, knowledge and LLM minds are not in this plan [Sec. 8]. No new primitive: this is the third of the
eight (`docs/utils/VISION.md` [Sec. 6]) as data plus handlers.

## 2. Findings

Read from the source before building; [Sec. 9] records what building changed.

1. **The brain has one routine.** `ExtrasBrain.Routine` rolls `WanderChance` (0.6) from the stream
   `extras:{id}:{minute}`; its only inputs are `mind.anchor`, position and the seed. `mind.goal.kind` is
   always `wander`.
2. **`eat`, `drink` and `sleep` already exist in `ops.toml`** (`eat`: object; `drink`: object, tile;
   `sleep`: self, object), tagged `need` or `rest`, with no handler. `OpCatalog.Register` refuses a
   handler with no `GameAction` schema, so each op needs both.
3. **Nothing marks an object as food.** `apple` is only a stackable `food` material kind; `bottle` is an
   empty glass kind. Handlers read components (`container`, `tool`), so edibility must be a component,
   never a kind name (`docs/PENDING.md`, "Recipes and supply").
4. **Water is walkable data.** `water_shallow` is `walkable` and `liquid`; `water_deep` is neither
   walkable nor reachable. A shallow tile is a legitimate drink source with no new object.
5. **The `Menu` is radius-1.** `Menu(actorId, x, y, z, radius)` lists what is on and next to a tile; it is
   a read with no lock, so a brain can call it at the tile it stands on. It cannot answer "where is food".
6. **`infinite` streams no objects.** A new endless game has only the spawn kit; the `test` world has
   apples on a shelf (open, so reachable) and in a closed chest. Without a supply an Extra can only be
   hungry, so Stage 3 gives each one a kit [Sec. 3, D6].
7. **Decay must not write.** `PITFALLS.md` [Sec. 3]: a move is one transaction and one `actor.moved` row
   already, and the log has no retention yet. A per-tick need event for every Extra would be the largest
   writer in the game. A level can be a pure function of time instead [Sec. 3, D2].
8. **`mind` is the only per-Extra persisted brain data**, written solely by `SetGoal`; `actor` rows have
   a migration chain at `0011_llm_call`. Stored JSON is read defensively.
9. **Dev-006 (fill and jump) is in flight** and also edits `OpCatalog.Register` and `GameAction.Ops`.
   Land one, rebase the other; the registrations are independent lines.

## 3. Decisions

Marked **approval needed** where a value or choice is open.

- **D1. A need is a level in 0..1 (1 = satisfied).** Three needs: `hunger`, `thirst`, `rest`. Rates,
  thresholds and night weights are data in `Data/needs.toml`, validated like `ops.toml`. Proposed values
  (**approval needed**, calibrate with the bench of Stage 6): hunger empty in 16 h awake, thirst in 8 h,
  rest in 17 h; seek below 0.5, urgent below 0.2.
- **D2. Levels decay lazily.** The row stores `{level, at}` per need (`at` = game minute of the last
  write); the current value is `max(0, level - rate x (now - at))`, a pure function of the clock. Nothing
  is written while time passes, a paused clock freezes it for free, and a restart changes nothing. Only an
  op that satisfies a need writes (a new `{level, at}`), and that write is in the op's own transaction.
- **D3. Storage: a nullable JSON `needs` column on `actor`** (`0012_actor_needs`), the same shape as
  `mind`. `NULL` means the actor has no needs. **Approval needed:** needs for Niko. Proposal: none yet. His
  row stays `NULL`, the ops still work for him (an apple is eaten, a line of text answers, no level
  moves), and a `STATUS` panel waits for vitals as `docs/PENDING.md` already says. One door, no private
  shortcut: Niko uses the same handlers; he just has nothing to satisfy.
- **D4. Edibility and drinkability are components.** `objects.toml` gains `[kinds.edible] satiety = 0.2`
  on `apple`; a material may carry `hydration` (`water_shallow = 0.5`). `drink` offers a tile whose
  surface has `hydration` (the actor on it or an orthogonal neighbour in reach) and an object with a
  `drinkable` component (none today; the slot exists for the first bottled drink). `eat` consumes one
  unit of the stack and clears the row at zero; both reuse the object helpers `take`/`drop` already use.
- **D5. `sleep` targets `self` only.** No bed kind exists; the `object` target of the op is left for it.
  A durative activity of `ceil((1 - level) x SleepFullMinutes)` minutes (480 proposed), completing to 1.0.
  An interrupted sleep recovers nothing (it is not productive work, `PITFALLS.md` [Sec. 3]).
  `sit` and `lie` are out: with no posture state and no seat data they would change nothing.
- **D6. Supply is a starting kit, not a system.** In a streaming world (`infinite`, which places no
  objects) each Extra gets a worn, open `backpack` with 2 to 4 apples, drawn from its own stream
  `population:kit` so `Population.Populate` and its golden stay byte-identical. Bounded worlds (`test`,
  `lab`) get no kit: they already lay out apples, and their object lists are pinned by the Python goldens
  that `StateDump` compares (`ActionScenarios.cs`). Shallow water is the drink source. When nothing is
  in reach the Extra stays hungry or thirsty and wanders; there is no starvation, because there is no
  health. **Approval needed:** this is deliberately thin, and real supply (shops, stock, prices) is
  Phase 2's pizzeria. The alternative, scattering food on generated terrain, would change `infinite`'s
  pure chunk contract (`CONTEXT.md`, Streaming worlds) and belongs to City authoring.
- **D7. The brain chooses among what the engine offers, then submits through the door.** For each need
  below its threshold the utility is `urgency - distance / 30`, with `urgency = (threshold - level) /
  threshold` and, for `rest`, a night weight (22:00 to 06:00, from `game_minute`); rest is sought below the
  threshold only at night and below the urgent level at any hour. A gain term would always be 1 while
  every threshold is at most 0.5, so it is not computed. The best
  available option wins, with the usual randomness among near-ties from the stream `needs:{id}:{minute}`.
  At the point of use the brain calls `Menu` on its own tile and submits the matching entry's own
  `action` through `Submit`, so the engine validates everything again. It never writes a level. Sleep
  happens at the Extra's anchor (its home proxy), so it walks there first.
- **D8. Where an Extra looks: a perception proxy.** `IEnginePort.Percepts(actorId, radiusM)` is a read
  that lists carried food, objects on tiles within `PerceptionRadiusM` (12) whose kind has `edible`,
  contents of open or lidless containers (the same rule `Menu` uses), and shallow-water tiles. It has no
  line of sight, because perception does not exist yet. **Approval needed:** this is the one place the
  rule "an NPC reacts only to what it perceived" is approximated; the method is named and documented as a
  proxy so Dev for witnesses and knowledge replaces its body, not its callers.
- **D9. No new event stream for decay; two events for outcomes.** `actor.consumed {op, kind, quantity,
  need, level}` and `actor.slept {level}`, committed by the engine, in the same transaction as the
  change. Not forwarded to Niko's feed: seeing another actor eat is perception, not this plan [Sec. 8].

## 4. Design

### 4.1 Model (sim.world, sim.db, sim.engine)

`NeedModel` is pure and lives with the data: `Level(need, now)`, `Urgency(need, now)`, `With(need, level,
now)`, `NightFactor(minute)`. `NeedCatalog.Load()` reads `needs.toml` and refuses a missing key, a
non-positive rate or an unknown field. `ActorRow.Needs` is a `JsonObject?` read through `NeedModel`, never
by key in a handler. `ActorState` gains `Needs` so the brain and the host read the snapshot. Migration
`0012_actor_needs` adds the column; `Schema0008.sql` stays untouched and the stepwise runner does the rest.

### 4.2 Ops (sim.engine, sim.events)

| Op | Target | Applies | Validate | Duration | Completes |
|---|---|---|---|---|---|
| `eat` | `object` | `edible` kind | in reach; not supported by another object | 3 min | one unit removed; `hunger = min(1, level + satiety)` |
| `drink` | `tile`, `object` | `hydration` surface / `drinkable` | tile in reach and walkable-liquid | 2 min | `thirst` up by `hydration`; object unit removed |
| `sleep` | `self` | always | clock not paused | by deficit, D5 | `rest = 1` |

An actor with `needs = NULL` completes the op with no level change. Handlers are plain
`OpHandler`s registered in `OpCatalog.Register`; no `ops.toml` change is needed, so no vocabulary changes.

### 4.3 Utility step (sim.minds)

`NeedsUtility` is a pure scorer over what the brain found: it turns the actor's own `Menu`, `Percepts` and
anchor into `NeedOption`s (an action to submit or a goal to walk to) and ranks them. `ExtrasBrain.Routine`
asks it first: an action is submitted, a goal becomes `SetGoal(kind = "seek", reason = "chosen")` over the
existing path machinery, and no option falls through to today's wander roll. It keeps no state: after arrival the goal is cleared, the next idle
tick sees the need still low, finds the source in reach through `Menu` and uses it. Percept scans run only
for an idle Extra with a need below threshold and at most once per `ScanEveryMinutes`, per Extra, derived
from `game_minute` (no stored timer), so a satisfied crowd costs nothing extra.

### 4.4 Visibility (sim.host, game.ui)

`WorldFrame` actors carry `Needs` (`HostNeeds`: three levels at the frame minute, or `null`). The
`DevConsole` NPC table gets `HUN`, `THI` and `RST` columns beside the existing activity text. No HUD change, no Figma change.

## 5. What must not break

- The engine is the only writer of state: the brain and the scorer read, then `Submit`/`SetGoal`.
- One action API: Niko gets `eat`, `drink` and `sleep` from the same generated menu, free text included.
- Determinism and replay: no wall clock, one seeded stream per decision, a replay re-submits the journaled
  `eat`/`drink`/`sleep` and never attaches the brain (`PITFALLS.md` [Sec. 3]).
- Saves: a pre-0012 save opens, gains `needs` for its Extras and loses nothing (`SaveCompatibility.cs`).
- `test` and `lab` world bytes and object lists, `infinite`'s pure chunks, and `Population` placement
  are unchanged: the kit exists only in streaming worlds, and is objects committed after placement, as
  the spawn kit is. `StateDump` keeps its fields, so the Python goldens still pass untouched.
- Tick cost: a crowd with needs ticks within 10 % of the same crowd without them (`EtherBound.Bench`, Release,
  speed 10). The plan approved "within 10 % of 64.9 ms/tick"; that figure is stale [Sec. 9], so the gate became
  relative, and the worst case misses it [Sec. 6].

## 8. Out of scope

- **Traits.** Utility weights per tag need trait data (`MINDS.md` [Sec. 8]); here weights are need-only.
- **Knowledge and witnesses.** Seeing another actor eat, line of sight, memory of where food was: the
  next Dev. `Percepts` is the seam [Sec. 3, D8].
- **Consequences of unmet needs** (mood, health, collapse) wait for vitals and the body system.
- **Supply, shops, prices, stock** (`docs/PENDING.md`, "Recipes and supply") and `cook`/`craft`.
- **Posture and beds:** `sit`, `lie`, a `bed` kind and the object target of `sleep`.
- **Social ops, Agents and LLM minds,** and anything a model proposes.
- **Event log retention** (open in `docs/PENDING.md`): this plan adds only rare outcome events and keeps
  decay off the log for that reason.

## 9. What building changed

- **Menu goldens.** `eat`, `drink` and `sleep` appear in menus the Python fixture cannot hold, so they join
  `build` in `AfterCutOver` (`MenuGoldens.cs`). `sleep` precedes `wait` in the catalog, which moved the
  free-text candidate number in `FreeTextHostRules.cs` and the own-tile op order in `OpsRules.cs`. No golden
  file was regenerated.
- **A crowd only decided once in a long while.** An Extra in a 15-minute `wait`, or walking a `wander` goal,
  never reached its next decision, and a scan runs on one minute in five. A needy Extra now re-decides on its
  scan minute while it only waits or wanders, and an interrupted wander goal is cleared (`actor.goal_set`
  reason `interrupted`) when it eats instead. Found by a pond scene that took 80 ticks to fail.
- **A `seek` goal ends a `wait`.** Setting a goal does not clear an activity; the first move step does, so
  the brain keeps walking a `seek` goal through the wait it was in.
- **Reading the Menu every idle tick cost +20 % for a needy crowd.** It is now read on the scan minute or at
  arrival on a `seek` goal (use is immediate there), which brought it to +12 %; carried food waits at most four
  minutes.
- **Clone cost.** Every move clones every actor row, so a deep-copied `needs` added about 20 % to a crowd
  tick. `ActorRow.Needs` is replaced whole and never edited, so clones share it.
- **A backfilled save is not replayable.** `BackfillNeeds` seeds needs and the kit while `EnsureWorld` opens a
  pre-`0012` save and journals nothing, so a journal replay of that save rebuilds its Extras at minute 0 with
  other needs and object ids. Same as the precedent for Extras added to an older save; no event, no regression.
- **Jev's candidates changed.** Niko's own-tile menu now offers `sleep` before `wait`, and `eat` beside food.
  `Llm.Bench -- --list` still finds every expected label among the candidates; the live Jev bench is worth re-running.
- **The 64.9 ms/tick figure is stale.** At the committed `v5.2.0` the same bench gives 3,945 ms/tick at 1,000
  Extras and 3,748 ms with this change and no needs, so the cause is older than this Dev (it is O(N^2) in
  actor-row clones per move). Recorded in `docs/PENDING.md`.

## TL;DR

Extras get hunger, thirst and rest as lazily decaying levels (a pure function of the game clock, one JSON
column, no per-tick writes), plus `eat`, `drink` and `sleep` as ordinary handlers that Niko shares. A
stateless utility step in `ExtrasBrain` picks the best satisfying option among a radius-limited perception
proxy and the engine's own `Menu`, walks there and submits through the one door; with nothing to do it
wanders as before. Starting kits and shallow water are the only supply; consequences, traits, knowledge and
supply systems are explicitly later. Seven decisions need approval before Stage 1: rates, Niko's needs,
the starting kit, the perception proxy, `sleep` on self only, no `sit`/`lie`, and no feed lines yet.

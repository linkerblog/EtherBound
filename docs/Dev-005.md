# Dev-005: Event bus and action pipeline (Server)

[Feature] [Engine] [Architecture] [Persistence]

Builds the spine that every later system hangs from. Every action takes the same path: validate,
resolve, commit, emit. What happened becomes a typed event, stored in the same transaction as the
state change and dispatched in order to subscribers. `move` is rewritten as the first verb handler.
The ad hoc clock listener and the direct hub calls become subscribers. Nothing new is visible in
the game. The value is that Dev-006 (verbs), Dev-007 (witnesses, knowledge) and Dev-008 (physics)
each become a new handler or subscriber, with no change to the core.

Reference: `docs/utils/VISION.md` [Sec. 4] (architecture), [Sec. 11] (determinism and replay) and
[Sec. 14] (what must not break); `CONTEXT.md` (Contracts, Measured pitfalls).

## 1. Decisions to approve

| Topic | Decision | Why |
|---|---|---|
| Who emits | **Only the engine produces events.** A system that wants something to happen submits an action, or later calls an engine API. It never enqueues an event itself | An event is a committed fact. If systems could emit freely, a fact could exist without the state behind it. This clarifies VISION [Sec. 4], "systems... emit new ones": they emit *through* the engine |
| Rejection vs failure | A **rejection** (a precondition fails, e.g. paused) changes nothing and emits nothing. A **failure** (a roll fails, from Dev-006 on) is a resolution and does emit | Real life: nobody can see an attempt that never started, but anyone can see a failed one |
| Move granularity | `actor.moved` fires only when the actor changes **tile or `h`**, never per 20 Hz input | Witnesses and rumors reason per tile. Per-input events would be about 20 rows a second of noise |
| Transient events | Every event class carries a `logged` flag. `clock.ticked` is dispatched but **not stored**. Everything else is stored | The minute is already stamped on every event. Storing ticks would add one row per game minute and say nothing |
| One log | The event log **is** the decision log. From Phase 3 on, model decisions are events of type `decision.*` in the same table | VISION [Sec. 11]: "every model decision is logged as an event". One ordered history, not two to reconcile |
| Order | One global `seq`, assigned under the engine lock. Dispatch is FIFO, breadth-first and never recursive | Deterministic order for replay and debugging. No handler ever runs inside another handler |
| Atomicity | Event rows are written in the **same transaction** as the state they describe | After a crash, the log and the world can never disagree |
| New game | `new_game` wipes the log, and `seq` starts again at 1 | The log is one run's history. A new seed is a new city |
| Subscriber errors | A handler exception is logged with its traceback and dispatch continues with the next handler | One broken system must not freeze the world |
| RNG persistence | **Not in this doc.** Saving the state of the RNG streams arrives with the first dice roll (Dev-006) | Today only world generation draws, and always from a fresh stream. Persisting state nothing uses would be dead code |
| Input replay | **Not in this doc.** The log records outcomes, not the 20 Hz inputs | Exact input replay needs the RNG persistence above, and that has no consumer yet |

The first row adds one sentence to VISION [Sec. 4]; see [Sec. 7], Closing.

## 2. What gets built

### 2.1 `server/src/etherbound/events/` (new module `server.events`)

`models.py`, Pydantic, with no engine or database import:

```python
class TilePos(BaseModel):
    x: int
    y: int
    h: int

class Event(BaseModel):
    logged: ClassVar[bool] = True
    seq: int = 0              # stamped by the engine
    game_minute: int = 0      # stamped by the engine
    type: str
    actor_id: str | None = None

class WorldGenerated(Event):   type: Literal["world.generated"]; seed: int; gen_version: int
class ActorSpawned(Event):     type: Literal["actor.spawned"]; kind: str; tile: TilePos
                               reason: Literal["created", "relocated"]
class ActorMoved(Event):       type: Literal["actor.moved"]; from_tile: TilePos; to_tile: TilePos
class ClockTicked(Event):      type: Literal["clock.ticked"]  # logged = False
class ClockChanged(Event):     type: Literal["clock.changed"]; speed: int; paused: bool
```

Give every `type` a default equal to its literal so that call sites do not repeat it.

`bus.py`:

```python
Handler = Callable[[E], Awaitable[None] | None]

class EventBus:
    MAX_CASCADE = 10_000

    def subscribe(self, event_type: type[E], handler: Handler[E], *, name: str) -> None
    def enqueue(self, events: Iterable[Event]) -> None   # engine only; synchronous, no await
    async def drain(self) -> None
```

- Matching uses `isinstance`, so `subscribe(Event, ...)` receives everything. Handlers run in
  subscription order.
- `drain()`: if a drain is already running (another coroutine, or a handler that submitted an
  action), return at once. The running drain will reach the new events. Otherwise pop events
  FIFO, await each matching handler, and stop when the queue is empty.
- A handler that raises: `logging.getLogger("etherbound.events").exception(...)` with the event
  `seq`, `type` and handler `name`, then continue.
- More than `MAX_CASCADE` events in one drain: log an error, clear the queue and return. The
  dropped events are already committed and logged. Only their dispatch is lost.

### 2.2 Action pipeline in `server.engine`

New `engine/verbs/__init__.py`:

```python
@dataclass(slots=True)
class ActionContext:
    session: Session
    world: WorldMeta
    actor: Actor
    grid: WorldGrid
    delta_seconds: float

class VerbHandler(Protocol):
    verb: ClassVar[str]
    def validate(self, ctx: ActionContext, action: Action) -> str | None: ...  # rejection reason
    def resolve(self, ctx: ActionContext, action: Action) -> list[Event]: ...  # mutates rows

def register(handler: VerbHandler) -> None   # raises on a duplicate verb
def handler_for(verb: str) -> VerbHandler
```

New `engine/verbs/move.py`: `MoveHandler`. `validate` returns `None`, because a blocked move is a
partial move, not a rejection (today's behaviour). `resolve` runs `move_in_world` exactly as
`submit` does today, sets `x, y, h, z` and returns `[ActorMoved]` only if
`(floor(x), floor(y), h)` changed.

`WorldEngine.submit(actor_id, action, delta_seconds)` becomes generic:

```text
async with lock:
    load world + actor                  (unknown actor → KeyError, as today)
    world.paused      → ActionResult(accepted=False, reason="paused"), no event
    handler.validate  → reason? → ActionResult(accepted=False, reason=...), no event
    events = handler.resolve(ctx, action)
    self._stamp_and_store(session, world, events)     # seq, game_minute, rows for logged events
    session.commit()
    self.bus.enqueue(events)                           # still under the lock: keeps seq order
await self.bus.drain()                                 # outside the lock
return ActionResult(accepted=True, ...)                # same shape as today
```

The same `_stamp_and_store` / commit / `enqueue`-under-lock / `drain`-outside pattern applies to
every mutating engine method:

| Method | Events |
|---|---|
| `ensure_world` (only when it generates chunks) | `world.generated`, then `actor.spawned` from `_ensure_actor` if it creates or relocates Niko |
| `new_game` | wipe the `event` table, reset `seq`; then `world.generated`, `actor.spawned` (`created`), `clock.changed` (always, since it is the run's initial clock) |
| `advance_time` (only when the minute advances) | `clock.ticked` (dispatched, not stored) |
| `set_clock` (only when `speed` or `paused` actually changes) | `clock.changed` |

- `ensure_world` stays synchronous. It enqueues, and the app's lifespan calls
  `await engine.bus.drain()` right after it.
- `seq`: the engine keeps `_next_seq`, loaded as `max(event.seq) + 1` (or 1) in `ensure_world`.
  Transient events take a `seq` too, so the stored log has gaps. That is expected.
- `set_clock_listener` and `_clock_listener` are deleted.
- New read method `read_events(after_seq, limit, type, actor_id)` returns stored rows in `seq`
  order.
- `WorldEngine.__init__` gets `bus: EventBus | None = None` and defaults to a new bus, so existing
  tests that build `WorldEngine(sessions)` keep working.
- `engine/actions.py`: `MoveAction`, `Action` and `ActionResult` are unchanged.

### 2.3 Storage in `server.db`

`models.py`, new row:

```python
class Event(Base):
    __tablename__ = "event"
    seq: Mapped[int]          = mapped_column(Integer, primary_key=True, autoincrement=False)
    game_minute: Mapped[int]  = mapped_column(Integer, nullable=False, index=True)
    type: Mapped[str]         = mapped_column(String(64), nullable=False, index=True)
    actor_id: Mapped[str|None]= mapped_column(String(64), nullable=True, index=True)
    data: Mapped[dict]        = mapped_column(JSON, nullable=False)
```

- `data` is `event.model_dump(mode="json", exclude={"seq", "game_minute", "type", "actor_id"})`.
- There is no foreign key on `actor_id`: the log is history and outlives the actors.
- Migration `server/alembic/versions/0003_event.py` creates the table and its three indexes, with
  a working downgrade. Existing saves get an empty log. No wipe.
- `server/alembic/env.py`: `fileConfig(config.config_file_name, disable_existing_loggers=False)`.
  This closes the "silenced server logs" loose end, and it is needed here because bus errors are
  reported through `logging`.

### 2.4 Wiring in `server.app` and `server.net`

- `create_app` builds one `EventBus` and passes it to `WorldEngine`. Then it subscribes:

| Event | Subscriber | Does |
|---|---|---|
| `ClockChanged` | `clock` (in `app.py`) | `clock.load(speed=..., paused=...)`, replacing the deleted listener |
| `ClockTicked`, `ClockChanged` | `hub.on_clock` | broadcast `tick(engine.get_state(), engine.world_info())` |
| `WorldGenerated` | `hub.on_world_generated` | broadcast `snapshot(...)`, then `reset_world()` |

- `on_tick` in `app.py` becomes just `await world_engine.advance_time()`.
- `WebSocketHub.handle`: after `engine.set_clock(...)`, remove the direct `broadcast(tick)`. The
  subscriber sends it, and only if something changed.
- `routes/api.py` `POST /api/game/new`: remove the two hub calls. The subscribers now do it
  before `engine.new_game` returns, because `new_game` drains.
- New `GET /api/events?after_seq=0&limit=100&type=&actor_id=` returns
  `EventsResponse { events: list[EventRecord] }`, where
  `EventRecord { seq, game_minute, type, actor_id, data: dict[str, Any] }`. `limit` must be
  between 1 and 500. This is the debugging window VISION [Sec. 11] asks for. The client does not
  use it yet.
- Acks stay as direct replies to the sender: they are responses, not world events.

## 3. Traps

1. **Deadlock.** Never `await bus.drain()` while holding the engine lock. A handler that submits
   an action would wait on the lock forever.
2. **Out-of-order dispatch.** `enqueue` must happen *inside* the lock, right after the commit. If
   it happens after the lock is released, a clock tick can slip in between and dispatch `seq` 6
   before `seq` 5.
3. **Re-entrant drain.** A handler that calls `engine.submit` makes `submit` call `drain()` again.
   The guard must make it return at once, otherwise dispatch becomes recursive and the order breaks.
4. **Slow handlers slow the player.** The WS input path awaits `drain()` before sending the ack.
   Handlers must be fast. Future slow work (LLM, Jev) goes into its own task and comes back as an
   action.
5. **Double tick broadcast.** If `handle()` keeps its own `broadcast(tick)` after `set_clock`,
   clients get two ticks per clock message. Remove it.
6. **`new_game` and the clock.** The scheduler used to be reloaded on every tick through the
   listener. It is now reloaded only on `clock.changed`, so `new_game` must always emit it, or the
   `Clock` keeps a stale speed or pause.
7. **Stamping.** The `game_minute` stamped on events is `world.game_minute` inside the same
   session, read before `advance_time` increments it. For `clock.ticked`, stamp the new minute.
8. **Database lock.** The migration test and manual checks need the server stopped (`CONTEXT.md`,
   Measured pitfalls).

## 6. Tests and checks

New `server/tests/test_events.py`:

1. The bus dispatches by `isinstance`, in subscription order. A `subscribe(Event, ...)` handler
   receives everything.
2. A handler that submits an action during a drain: its events are dispatched *after* the
   remaining queued ones (FIFO), never nested.
3. A handler that raises is logged, and the next handler and the next event still run.
4. A self-feeding handler stops at `MAX_CASCADE` with an error log and no hang.
5. Walking across a tile boundary stores exactly one `actor.moved` with the right `from_tile` and
   `to_tile`. Moving inside one tile stores nothing.
6. A move while paused stores nothing and dispatches nothing.
7. `new_game` leaves exactly `seq` 1 `world.generated`, 2 `actor.spawned`, 3 `clock.changed`.
8. `advance_time` dispatches `clock.ticked` and stores no row.
9. `set_clock` stores `clock.changed` on a change and nothing when the values are unchanged.
10. After a restart (a new `WorldEngine` on the same database), `seq` continues at `max + 1`.
11. Registering two handlers for `move` raises.

## TL;DR

Adds an in-process event bus (`server.events`) and turns `submit` into a generic pipeline:
validate, resolve, commit, emit. `move` is its first verb handler. Events are typed Pydantic
models with one global `seq`. They are stored in a new `event` table (migration `0003`), in the
same transaction as the state they describe, and dispatched FIFO outside the engine lock. Only
the engine emits. Rejections emit nothing, and moves are logged per tile, not per input.
`clock.ticked` is dispatched but not stored. The clock listener and the direct hub calls become
subscribers. `GET /api/events` exposes the log for debugging. The alembic logging fix rides
along. Nothing changes for the player. Dev-006 (verbs), Dev-007 (witnesses) and Dev-008
(physics) plug in as handlers and subscribers.

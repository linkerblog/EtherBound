# Dev-017: Radial action menu (V)

[Feature] [UI] [Accessibility]

Acting on Niko's own tile means an exact right-click on the isometric tile he stands on, which
rarely is the pixel under the cursor, and then reading a list. This doc adds a radial menu: `V`
opens the entries the server builds for Niko's tile in a ring around him, and a click, a number or
Enter runs one. The server still builds every entry; the client only places and renders them
(`docs/utils/STYLEGUIDE.md` [Sec. 8]).

Reference: `docs/utils/VISION.md` [Sec. 7] (generated menus); `docs/utils/STYLEGUIDE.md` [Sec. 8]
(context menu), [Sec. 16] (keyboard paths) and [Sec. 3] (game semantics); `CONTEXT.md` (Menus
contract); `docs/Dev-016.md` (list menu on `E`, hover target), which stays a separate interaction.

## 0. Current state (measured before this doc)

- The only way to open the menu is `pointerdown` with the right button
  (`web/src/game/MapScene.ts`); a
  keyboard-only player cannot reach any action.
- The menu is anchored to the cursor, so the options for Niko's own tile (self, held and worn
  objects, the surface under him) need a right-click on his feet.
- `WorldEngine.menu(actor_id, x, y, z)` already returns every applicable entry for any tile,
  computed for Niko; on his own tile it adds `self`, held and worn objects and open contents
  (`engine/world.py`, delegated to `engine/menu.py::build_menu`). Nothing new is needed from the
  server.

## 1. Decisions

| Topic | Decision | Why |
|---|---|---|
| Key | `V` toggles the radial; `Esc` closes it; ignored while the free-text input or the new-game dialog has focus, and with Ctrl/Meta/Alt held | `V` is free (`E` is Dev-016's list menu); typing `V` in the input must not open a menu |
| Target | The 3×3 tile square centred on Niko at the moment of opening (his tile ± 1, same `z`), taken from the live prediction, minus any tile a wall actually cuts off | One key, no aiming; every tile a metre away is worth showing, but a wall between Niko and a tile must still mean "not from here" |
| Reach vs walls | An orthogonal neighbour needs `in_close_reach` (open shared edge); a diagonal neighbour needs at least one of its two orthogonal sides open (`in_close_reach` on either) — cutting the corner is allowed, being boxed in on both sides is not | Reuses `in_close_reach` (`engine/ops/base.py`), the same primitive `take`, `open`, `dig`, `push` and `hit` validate against, instead of inventing a second wall rule; corner-cutting is the usual tile-game convention for "can I see/reach around this corner" |
| Diagonal actions | Included as candidates like any tile, but `in_close_reach` itself still refuses anything beyond one orthogonal step, so ops gated on it (take, open, dig, push, hit) validate a diagonal target as "out of reach" and show dimmed; ops that don't check physical reach (`inspect`) work normally | Matches "every entry the server returns, available or not": the ring shows what is *there* one tile away, physical actions stay bound by the one rule every op already agrees on, no new exception for diagonals |
| Entries | Every entry the server returns, available or not | The client never hides or invents an op; unavailable options stay visible and explain themselves |
| Layout | Superseded by `done/Fix17.md` [Sec. 1]: level 1 is one slot per verb on these rings, level 2 places a verb's targets by tile direction. Originally: all entries on concentric rings around Niko: 8 per ring, first ring at the top running clockwise, alternate rings offset by half a step | Every option is placed, none is paged away or dropped, and labels do not line up across rings |
| Centre | Superseded by `done/Fix17.md` [Sec. 1]: in level 2 the hub holds the verb header and Niko's own-tile rows. Originally: a hub shows the target line (`Asphalt · 1 m`), and for the focused entry its label, subject and reason | The ring labels stay short; the details live where the eye already is |
| Pointer | Hovering a slot focuses it; clicking a slot picks it; clicking the hub closes | Conventional radial behaviour |
| Keyboard | Level 1 unchanged; level 2 (numpad directions, `Esc`/`Backspace` back) is in `done/Fix17.md` [Sec. 1]. Originally: ←/↑ and →/↓ cycle the ring, `1`–`9` focus by position, Enter/Space pick, `V`/`Esc` close | STYLEGUIDE [Sec. 16]: every action has a keyboard path |
| Unavailable | A dimmed slot, never `disabled`; picking it shakes the hub instead of acting | The reason is readable and the row stays focusable, like `ContextMenu` |
| Follow | While open, the radial re-anchors on Niko every 100 ms | Niko can walk the camera while the menu is open |
| Markers | `illegal` red, `ether` magenta, `violent` get a `!`; colour is never the only signal | STYLEGUIDE [Sec. 3], [Sec. 16] |

## 2. Client

**web.game** (`MapScene.ts`)
- `PlayerAnchor` type (`ContextTarget`): Niko's tile plus the page point his feet are drawn at.
- `playerAnchor(): PlayerAnchor | null` maps the current world point through
  `camera.worldView` and `camera.zoom`, and returns `null` before the scene is built.
- `createGame` accepts an optional `onScene(scene)` callback so the overlay can hold the live
  `MapScene`; the existing arguments are unchanged.

**web.ui** (new `radialMenu.ts`; `App.tsx`, `ContextMenus.tsx`, `styles.css`)
- `radialMenu.ts` (pure): `radialSlots(entries)` places every entry on rings and returns offsets
  from the hub; `firstAvailable(entries)` and `stepFocus(current, step, length)` drive focus.
  `RADIAL_CAPACITY`, `RADIAL_BASE_RADIUS` and `RADIAL_RING_STEP` are the tunables.
- `App.tsx`: `radial` state, `radialOpen`/`radialRequest` refs, `openRadial()` (fetches
  `/api/menu` for Niko's tile), `closeRadial()`, and the `V`/`Esc` keys. Opening the radial closes
  the context menu and vice versa; `pickEntry` closes both. A 100 ms interval re-anchors the
  centre while open.
- `RadialMenu` (`ContextMenus.tsx`): an SVG draws one line per slot; each slot is a `button` with `role="menuitem"`
  and `aria-disabled`; the hub shows the target and the focused detail. Capture-phase keys match
  `ContextMenu`, so Enter picks here instead of focusing the input line.
- `styles.css`: `.radial`, `.radial-lines`, `.radial-hub`, `.radial-slot` and its `off`/`illegal`/
  `ether`/`violent`/`focus` variants, plus the `radial-shake` retrigger (disabled under reduced
  motion).

**server.app** (`routes/api.py`) / **server.engine** (`engine/world.py`, `engine/menu.py`)
- `GET /api/menu` gains an optional `radius: int = Query(0, ge=0, le=1)`; the right-click menu
  keeps the default (one tile, today's behaviour unchanged).
- `WorldEngine.menu(actor_id, x, y, z, radius=0)` forwards it to `build_menu`.
- `build_menu(..., radius=0)` always scans the origin tile; at `radius=1` it also scans the four
  orthogonal neighbours for which `in_close_reach(ctx, nx, ny)` is `True`, and each of the four
  diagonal neighbours for which `in_close_reach` allows at least one of its two orthogonal sides
  (`ORTHOGONAL_STEPS`/`DIAGONAL_STEPS` in `engine/menu.py`) — up to nine tiles — and unions every
  tile's `TileTarget`/`ObjectTarget`/`EdgeTarget`/`ActorTarget` candidates. `SelfTarget` and the
  carried/worn objects are still added exactly once, gated on the scanned tile matching the actor's
  own tile, so scanning nine tiles does not duplicate them. The hub's `target` label keeps
  describing the origin tile's own surface, from `chosen`/`label` computed on `(tile_x, tile_y)` as
  now.

**web.net**: regenerate `schema.d.ts` for the new `radius` query param (`npm run check:web`'s
schema diff step).

**web.ui** (`App.tsx`): `openRadial()` adds `radius: "1"` to its query; `openMenu()` (right-click)
sends none, so it keeps resolving to a single tile. `radialMenu.ts` needs no change: it already
lays out whatever flat `entries` list the response carries, regardless of which tile each one
came from.

## 3. What must not break

- The client never adds or removes an op; it sends back `entry.action` unchanged.
- `submit` still re-validates everything; `/api/menu` stays a lock-free read.
- WASD, zoom keys, Enter-to-input, right-click and the free-text field keep working while the
  radial is closed.
- `V` typed in the input does nothing to the menu.
- Closing the radial leaves no request applied: a late response is dropped by its token.
- The right-click menu keeps its exact-tile behaviour: `radius` defaults to 0 server-side, and
  `openMenu()` never sends it.
- Self, held and worn entries appear exactly once per radial open, even though `build_menu` now
  scans up to nine tiles.

## 4. Acceptance

### Automated

1. `web/tests/radial-menu.test.ts`: every entry is placed exactly once; the first ring starts at
   the top and runs clockwise; overflow goes to a wider ring without dropping an option; focus
   starts on the first pickable option and wraps.
2. `npm run check:web` (schema export, `schema.d.ts` diff, web tests, production build) and
   `npm run check`; `web/tests/visual/spawn.spec.ts` baselines unchanged (the radial is closed at
   spawn).
3. `server/tests/test_physics.py::test_menu_radius_reaches_open_neighbours_and_stops_at_walls`:
   objects one tile away (east, north) are absent at `radius=0`, present at `radius=1`, and a
   wall on the shared edge removes only the blocked neighbour's entries.
   `test_menu_radius_reaches_diagonal_neighbours_around_open_corners`: a diagonal object is
   reachable with no walls, stays reachable once only one of its two sides is walled (the corner
   can still be cut), and disappears once both sides are walled.

### Manual

4. Superseded by `done/Fix17.md` [Sec. 4] manual 4, which checks the two-level layout. Originally:
   Manual (GUI, x1 and x4): `V` opens the ring around Niko showing `Wait` and `Inspect` at spawn;
   walking keeps the ring centred on him; hover and ←/→/digits move the hub detail; Enter runs the
   focused op and `V`/`Esc` close; a dimmed slot shakes the hub with its reason; holding a shovel
   adds it to the ring; an object placed one tile away, including diagonally (not on Niko's own
   tile), also appears in the ring, dimmed if the op it offers cannot reach diagonally. Reason:
   feel, anchoring and layout need a screen.
5. Manual: `V` does nothing while the input line has focus; `Narrator`/keyboard-only play can
   reach every action. Reason: focus behaviour needs a browser.

## TL;DR

`V` opens a radial menu of the server-built entries for the 3×3 tile square centred on Niko, minus
whatever a wall actually cuts off, arranged on rings around him, with a hub that explains the
focused option. It follows him while open and is fully usable by mouse or keyboard. `/api/menu`
gains an optional `radius` param (0 by default) that reuses the engine's existing `in_close_reach`
primitive for orthogonal neighbours and a corner-cutting rule built on it for diagonals; the
right-click list menu keeps its exact-tile behaviour untouched.

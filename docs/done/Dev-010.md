# Dev-010: Endless procedural world and minimap

[Feature] [World] [Engine] [Architecture] [UI]

Today every generator builds a bounded world up front and the engine persists and loads every chunk.
This plan adds a generator whose chunks are a pure function of `(seed, options, cx, cy)`, created on
demand around Niko and kept only while needed, so the terrain has no edge, plus a minimap that shows
the ground around him. It is a contract change for the world layer, not "one more generator". Roads,
buildings and the city are a later Dev [Sec. 6].

## 2. Findings

Read from the source; nothing here was run. Items 2 to 8 are finite-world assumptions that Stage 2
must remove, listed so they are not discovered mid-build.

1. **Generators are all-at-once.** `GeneratorSpec.Generate` returns a complete `GeneratedWorld`
   (`World/Gen/Generators.cs`); `test` is 8×8 chunks and `lab` 4×4.
2. **`EnsureWorld` regenerates when the save has no chunk rows** (`regenerate = fallback || !hasChunks
   || world.GenVersion < spec.Version`, `Engine/WorldEngine.cs`). A fresh endless save stores nothing
   until something is modified, so it would regenerate on every open, and `Wipe` drops every object
   that is not carried.
3. **`Database.LoadGrid` loads every chunk and level**; `CommitWorld` marks every generated chunk
   dirty (`Engine/WorldSetup.cs`), so the whole world is written once.
4. **A read can trigger a load.** `WorldGrid.Chunk(cx, cy)` already has an optional `chunkLoader`
   and a `_missingChunks` set (`World/WorldGrid.cs:72-89`), unused today. Reads that are not
   journaled (`Menu`, `Pick`, `ChunksNear` in `Host.Publish`, `Nav`) would trigger loads, so a load
   must write nothing: no rows, no events, no `MarkChunk`. Only a mutation persists a chunk
   (`ObjectHelpers.BumpChunk` already does). That also keeps replay exact.
5. **Object ids depend on order.** `Session.AddObject` assigns max+1, so objects generated on load
   would make ids depend on read order. `LoadObjectIndex` indexes only chunks present at load, so a
   loader must call `SetChunkObjects`; `ObjectHelpers.TileObjects` scans every object per chunk.
6. **`Spawning.SpawnPoint` falls back by iterating `grid.Chunks.Keys`**, empty in a lazy grid.
7. **`WorldGrid.AddChunk` calls `InvalidateNavigation()`**, clearing the standing and step caches on
   every lazy load, possibly mid-A*. `Nav.FindPath` already caps at `maxExpansions = 20000`, so an
   unreachable goal ends, but each expansion may now generate a chunk.
8. **Nothing evicts chunks**, and `ChunkPayload.Of` scans `grid.Levels` linearly
   (`Engine/Payloads.cs:73`).
9. **`ValueNoise` repeats.** `Value` masks with `& 255` (`World/Gen/ValueNoise.cs`), so each octave
   repeats every 256 lattice cells (about 6 km for the third octave at scale 96). It stays: the
   `test`/`lab` goldens pin its output.
10. **Walkability constrains terrain.** `rock` and `water_deep` are not walkable; `water_shallow`,
    `sand`, `grass`, `dirt`, `topsoil` and `clay` are (`Data/materials.toml`), and a step is at most
    one half-metre cell. Unconstrained rivers and peaks would cut the world in pieces.
11. **Budgets already missed.** `docs/PENDING.md` lists the first host frame (50 ms target) and chunk
    crossing (40 ms target, measured 42.3 and 42.6 ms) as unmet; this plan must not worsen them.
    `BannedSymbols.txt` also bans `HashCode`, `string.GetHashCode`, `Parallel` and `Task.Run`.

## 3. Decisions

Marked **approval needed** where the choice is open.
- **D1. Scope.** Terrain, biomes, water, chunk streaming and the minimap. Roads, buildings, objects
  scatter and the city are excluded; they answer "City authoring" in `docs/PENDING.md` and tie into
  NPC construction. This pulls the wilderness half of Phase 4 forward as a new Phase 1.6 in
  `docs/utils/ROADMAP.md`. **Approval needed.**
- **D2. New generator key `infinite`** ("Endless world", version 1). `test` and `lab` are untouched
  (`worlds.json`, `world-parity.json` pin their bytes). `Generators.Default` stays `test` so sim
  tests and goldens keep running; the Godot client's `--generator` default becomes `infinite`.
  **Approval needed** for the client default.
- **D3. Per-chunk pure contract.** `GeneratorSpec` gains an optional `Stream(seed, options, registry)`
  factory returning an `IChunkSource` (`Generate(cx, cy)` and the bare surface `Sample(x, y)` the
  minimap reads); a spec with it is a *streaming* generator, the others keep `Generate`. Output depends only on seed, options,
  version and coordinates, never on visit order. Negative coordinates work end to end.
- **D4. A pristine chunk is a cache, not state.** The loader reads the `chunk` row first and
  generates when there is none; it never writes. Persisted rows are the modified chunks only, so a
  save stays small. Each persisted chunk keeps its own `gen_version`.
- **D5. Noise.** New `HashNoise`: an integer mix (splitmix64) of `(seed, octave, x, y)`, with no
  lattice and no period, and per-chunk randomness derived from the same mix. `ValueNoise` is not
  changed.
- **D6. Terrain model.** `TerrainField.At(x, y) -> (h, surfaceMaterial)` is pure and chunk-independent,
  so borders cannot show seams. Layers: continental elevation (about 512 m scale), hills (about 96 m),
  moisture (decides grass, dirt, topsoil, sand, clay), lakes below a sea level, rivers from ridged
  noise, and rock only on peaks. Only existing materials; strata per chunk come from the biome.
  Option fields stay few (`relief`, `water`, `mountains`), so `GeneratorPanel` builds them as is.
- **D7. Never partitioned.** Deep water only in patches inside a shallow band, rivers are shallow
  lowland depressions (at most 2 m deep) and rock only as scattered outcrops, so every obstacle can be
  walked around or waded. Measured, not proved: a lake can be about 100 tiles of deep water across, so
  the rule is reachability, not run length: at least 97 % of the walkable tiles in a 400 m box
  around spawn are connected to it, and a budgeted A* reaches targets 500 m out in at least 7 of 8
  directions [Sec. 5]. Islands are allowed, spawn is never on one (D8).
- **D8. Spawn.** `spec.Spawn(seed, options)` stays pure and cheap: a spiral search over
  `TerrainField` from the origin for a walkable tile whose 60-tile neighbourhood is connected (budgeted
  flood fill). `Spawning.SpawnPoint` keeps its existing signature and uses it first.
- **D9. Objects.** Streamed chunks carry none. `NewGame` places the spawn kit (shovel, backpack,
  chest with food, sledgehammer) next to spawn through the existing `CommitObjects`, so those rows
  are persisted at creation. World scatter needs its own id and indexing policy: a later Dev.
- **D10. `gen_version` policy.** A streaming save is **pinned**: `EnsureWorld` never regenerates it
  and never wipes objects. A later change to terrain output ships as a new registered version
  that coexists with version 1, never as a bump in place. Alternative: regenerate pristine chunks
  and accept seams beside modified ones. **Approval needed.**
- **D11. Memory.** Evict clean chunks farther than 4 chunks from every actor, never one with
  uncommitted changes; a reload goes through the loader, so it is identical.
- **D12. Coordinate limit.** Chunk coordinates are limited to ±32,768 (about ±1,048 km), enough for
  `int` tiles; render precision far out is out of scope [Sec. 6], measured in Stage 3.
- **D13. Minimap content: local window, no memory.** About 256 m around Niko, no persisted
  knowledge, no migration. The follow-up Dev can add an explored-chunk set (fog) and a full `M`
  map on the same sampler. Alternatives: fog from the start (persisted explored set, migration
  `0012`, an engine-written `map.explored` event) or a fully revealed map. **Approval needed.**
- **D14. Minimap data.** `MapSampler` (sim.world, pure) turns a chunk into 16×16 colour cells, one
  per 2×2 tiles: material colour from the registry, shaded by the height difference to the north-west
  neighbour. Modified chunks (keys from one `SELECT cx, cy FROM chunk` at load) are read through the
  grid, so a dug hole shows. The host caches map chunks and rebuilds only those entering the
  8×8-chunk window; the result is a new immutable `WorldFrame.Minimap` field, carried over by
  reference like `HostChunk`. The client only paints it and adds Niko's marker. Measured (Release): 0.3 ms per
  chunk, so a crossing's 9 new chunks cost about 2.7 ms and the first window 17 ms on the sim thread; after the
  first window at most 9 chunks are coloured per publish (the rest draw dark a moment), so no off-thread work.
- **D15. Minimap placement and orientation.** A `MAP` panel first in the status column, with a 256×256
  design-unit square (`HudLayout.MinimapSize`, centred inside the column's padding). Orientation, changed
  from the plan's `CompassOverlay`: axis-aligned, north (world -y) up, east right, which is what W and D do;
  an iso-rotated map would need a circular mask. The Figma update goes to `docs/PENDING.md`.

## 4. Changes by stage
### Stage 1: terrain field
- `World/Gen/HashNoise.cs`, `World/Gen/TerrainField.cs` (pure, no grid, no database).
- Golden `Goldens/endless-terrain.json`: hashes of a fixed chunk list at seed 7, regenerated only
  with a version change.

### Stage 2: streaming contract
- `GeneratorSpec.GenerateChunk`, the `infinite` spec, and `World/Gen/EndlessWorld.cs` building a
  `Chunk` from the field; `Spawning.SpawnPoint` per D8.
- `WorldEngine`: a loader passed to `WorldGrid` that reads the DB row else generates, calls
  `SetChunkObjects`, and writes nothing. `EnsureWorld` and `NewGame` take a lazy path for streaming
  specs: no `Generate`, no bulk `CommitWorld`, no `LoadGrid`; `hasChunks` is not a regeneration reason.
- `Database`: single-chunk read (`chunk` plus its `chunk_level` rows) for the loader and the modified
  key list. No schema change, so no migration.
- `WorldGrid`: `AddChunk` from the loader must not invalidate navigation mid-search. Options: batch
  the revision bump per loader call, or key the standing cache per chunk. Pick one in the
  implementation and record it in `docs/utils/PITFALLS.md` [Sec. 2]. Add an eviction method and a
  per-chunk level index used by `ChunkPayload.Of`.

### Stage 3: host and client
- `SimulationHost` keeps radius 2 for the frame; prefetch is one ring farther (radius 3) at one chunk
  per host loop turn, so a crossing finds the next ring already generated. Generation cost per chunk
  is about 2 ms (`chunkgen` mode of `sim/EtherBound.Bench`: 1.1 ms average, 2.2 ms p95, Release).
- `WorldClient`: `--generator` default `infinite`; it already builds from whatever chunks the frame carries.
- Measure and record in `docs/PENDING.md`: chunk crossing (same 15-chunk scenario as the existing
  42.3/42.6 ms) and the first frame, before and after; and a manual far-origin check (Niko placed
  about 20 km out in a throwaway save) to see float32 jitter.

### Stage 4: minimap
- `World/MapSampler.cs`, the `HostMinimap` record, the frame field and its cache in `SimulationHost`.
- `game/ui/MinimapPanel.cs` (texture from the frame bytes, Niko marker, north tag), `HudLayout.Minimap`, the
  panel mounted in `GameHud`, and a pure `MinimapModel` (view region, marker) so tests need no scene.

## 6. What must not break, and out of scope

**Must not break.** The world engine stays the only writer (the loader and the sampler write
nothing). One action API; the client never simulates (it paints frame bytes and never samples
terrain). Determinism: no `System.Random`, no wall clock, no `HashCode`. `test` and `lab` bytes and
their goldens. Saves from before this change open as they did (`SaveCompatibility.cs`); no schema
change here. Replay of recorded journals. `Architecture.cs`: database access stays inside the engine.

**Out of scope.** Roads, buildings, scatter objects and any structure crossing chunk borders (they
need a site-based stamping contract, decided with City authoring); fog or a full world map (D13);
biome gameplay; transport; a floating-origin fix for float32 precision, only measured here; Extras
beyond spawn.

## TL;DR

`infinite` is a new streaming generator: chunks are a pure function of seed and coordinates, built
from a period-free hash-noise field with biomes, lakes, fordable rivers and rock peaks with passes,
created on read without writing anything, evicted when far and persisted only once modified, so saves
stay small and replay exact. `test` and `lab` are untouched. The minimap is a pure sampler of the same
field, a local window around Niko sent as a cached frame field and painted by the client; fog and a
world map come later. Docs go first; approvals needed: D1, D2, D10, D13 and D15.

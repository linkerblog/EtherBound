# Dev-007: Jev runtime and free-text interpretation

[Feature] [Minds] [Host] [LLM]

The Enter box exists and does nothing: `WorldClient.cs:178` echoes the text into the feed and drops
it. This plan makes it the first LLM-driven way to play. The player types what Niko does, Jev
(TypeSafe `choice`) picks one entry among the actions the engine already generates for the spot,
and the engine validates and commits it through the ordinary action API. No model writes state, no
new op, no schema change. It also settles the open question "Jev runtime after Dev-025" in
`docs/PENDING.md`.

## 1. Findings

Read from the source and from NikoStory; nothing here was run, and the vendor API was not
re-checked against its current docs.

- **Free text has a hook and no consumer.** `GameHud.FreeTextSubmitted` fires on Enter; the only
  subscriber prints `> text`. The `LLM` tab (ALT+3) is a placeholder.
- **The candidate set already exists.** `WorldEngine.Menu(actorId, x, y, z)` returns every op x
  target that applies, each with its `action`, `available` and `reason`, and hides what Niko cannot
  perceive (closed containers). That is the closed list a `choice` question needs.
- **The sim cannot own the network.** `BannedSymbols.txt` bans threads, timers and wall clocks, and
  the sim runs on the host's one thread. An HTTP client with timeouts belongs outside `sim/EtherBound.Sim/`.
- **Jev is a hosted HTTP service, not a library.** NikoStory's `server/src/llm/typesafe.ts` calls
  `POST https://api.typesafe.ai/v1/systemone` with `{ state, model, questions }`. A question is
  `choice` (option name to description; returns `choice`, `confidence` 0..1 and the full
  `probabilities`) or `noul` (probability of yes). All questions of one request run in parallel
  against the same `state` (one text string). Documented price there: $0.042 per million input
  tokens, output free. Default model id there: `jev-latest`. So there is nothing to port and no
  sidecar to run: the answer to the PENDING item is a thin C# client.
- **NikoStory never measured Jev for intent.** Its `Dev-005` left "adopt Jev for intent" blocked on
  a benchmark that never produced numbers. This plan therefore ships with a bench step ([Sec. 4]).
- **NikoStory's mock was unsafe for this use.** Without a key a `choice` answered its first option.
  For a guardrail that is harmless; for interpretation it would execute an arbitrary action.

## 2. Decisions

Marked **approval needed** where the choice is open.

- **D1. New module `sim.llm`** at `sim/EtherBound.Llm/` (namespace `EtherBound.Llm`). It references
  `EtherBound.Sim` for types; `EtherBound.Sim` never references it; `EtherBound.Host` does. The
  architecture test keeps both directions honest, so determinism rules and `BannedSymbols.txt` stay
  untouched.
- **D2. `IJev` with three implementations.** `IJev.Ask(state, questions, ct) -> JevResult`.
  `TypeSafeJev` (HTTP, `HttpClient` injected so tests use a fake handler), `ScriptedJev` (tests:
  canned answers by question id) and `NoJev` (no key: every call returns `Unavailable`). **Approval
  needed:** `NoJev` never guesses. Without a key the feed says "free text needs a Jev key" and
  WASD, the right-click menu and `V` keep working. This replaces NikoStory's first-option mock.
- **D3. Key and config live outside the repo.** `ETHERBOUND_TYPESAFE_KEY` in the environment, or
  `llm.json` in the user data dir (the same folder as the default save, never inside `data/`).
  The key is never logged, never put in a `WorldFrame`, event or exception text. The LLM tab shows
  only "key set / not set" and the model id (default `jev-latest`).
- **D4. One question over whole entries, not over op then target.** Questions in one request are
  independent, so "which op" and "which target" cannot be chained. The state lists the candidates
  as `e01 = dig: the grass tile to the north`, `e02 = take: the shovel`, and so on, built from
  `Menu` entries within the radial menu's radius. **Changed while implementing:** entries the engine
  would refuse are kept, marked "not possible right now", after the available ones and only up to the
  cap; the first run showed that on asphalt "dig here" would otherwise answer "nothing matches". Order
  is distance then catalog order, capped at 40 (provisional). Questions:
  `entry` (`choice`: every `eNN` plus `none`) and `fits` (`noul`: does the text ask for something
  the candidates cover?). Labels are the generated menu labels, so no prose is authored.
- **D5. Confidence decides, thresholds are data.** `Data/llm.toml` holds `accept` (0.75), `confirm`
  (0.40), the candidate cap and the timeout (15 s); all provisional.
  - `entry` is a candidate and `confidence >= accept` and `fits >= 0.5`: submit its action.
  - Between `confirm` and `accept`: the feed asks "Did you mean: <label>? Enter = yes". Enter on an
    empty box or "yes" confirms, "no" drops it, any other text is a new line (`FreeTextFlow`). The
    confirmation is client-side presentation; only the confirmed action is submitted.
  - A refused entry chosen at `confirm` or above is `Blocked`: nothing is submitted and the feed says
    "CAN'T <label> · <the engine's reason>".
  - `none`, below `confirm`, or `fits < 0.5`: nothing is submitted; the feed says nothing in reach
    matches. VISION [Sec. 7]: narrative-only, no mechanical effect.
- **D6. Re-validation on arrival.** The world keeps ticking while Jev thinks. The chosen `action`
  goes through `SubmitAction` like any command; the handler's `Validate` rejects it when the object
  moved or the tile changed, and the feed shows the engine's own reason. The host never trusts the
  snapshot the question was built from. VISION [Sec. 4] "Async LLM".
- **D7. One interpretation in flight.** A new Enter cancels the pending call. A timeout, an HTTP
  error or a malformed answer is one feed line and no state change.
- **D8. The decision is logged as an event.** New `WorldEngine.RecordDecision(actorId, kind, json)`
  commits an `llm.interpreted` event in the same transaction rules as any event: text, model,
  candidate count, chosen entry, `confidence`, top three `probabilities`, tokens, cost. It is the
  engine, not the host, that stamps it. The submitted action is journaled normally, so a replay
  resubmits the final action and never calls Jev. **Approval needed:** whether the raw text is
  stored in the event (useful to debug, but the log grows; see the retention item in
  `docs/PENDING.md`). Recommended: yes, truncated to 200 characters.

## 3. Changes

- `sim/EtherBound.Llm/`: `IJev`, `JevQuestion` (`Choice`, `Noul`), `JevAnswer`, `JevResult`,
  `TypeSafeJev`, `ScriptedJev`, `NoJev`, `LlmConfig` (key and model resolution), and
  `FreeTextInterpreter` (builds the state and questions from a candidate list, maps the answer to
  a decision `Accept(action)`, `Confirm(action, label)`, `Reject(reason)`). Pure except for `IJev`.
- `Data/llm.toml`: thresholds, cap and timeout, embedded like the other data files.
- `sim.engine`: `RecordDecision`; an undeclared `kind` throws, so only declared kinds
  (`llm.interpreted`, `llm.narrated`) can be written. It journals a `record_decision` input, so
  `InputReplay` re-commits the recorded decision and a replay's event sequence is identical.
- `sim.host`: command `InterpretText(request, text)`. On the sim thread it reads Niko's `Menu`
  into an immutable candidate list; the call to Jev runs off the sim thread; the answer comes back
  as an `InterpretDone` command, so the sim thread stays the only mutator. Response
  `HostInterpretResponse { Kind: Accept | Confirm | Blocked | Reject | Unavailable, Label, Message,
  Action }`. The code lives in `SimulationHost.Llm.cs` (a partial class), not in the main file.
- `game.app` / `game.ui`: `FreeTextSubmitted` goes through `FreeTextFlow`, which asks the host and
  writes the feed (`>` echo, then `->` the chosen label, or the confirm, blocked or reject text).
  The LLM tab is Dev-008's panel; the Jev rows of it are fed by this Dev.
- Docs: `CONTEXT.md` (module table, "Not yet present"), `docs/utils/VISION.md` [Sec. 13] (Jev
  runtime settled), `docs/PENDING.md` (delete the Jev runtime item), the system map, and
  `docs/utils/VERSION.md`. Record the order change first, see [Sec. 6].

## 4. Bench before trusting it

`dotnet run --project sim/EtherBound.Llm.Bench` (a project beside `EtherBound.Bench`) runs a fixed corpus of 40 sentences (English, ten of them Spanish, ten
with no matching candidate) against the `test` world's menu at the spawn, with a live key, and
prints accuracy, the `none` rate, p50/p95 latency and cost per call. The decision rule is written
here before the numbers: **adopt `accept = 0.75` only if at least 85 % of the sentences with a
matching candidate are submitted correctly and fewer than 5 % of the sentences with none are
submitted at all.** Otherwise raise the threshold or fall back to the OpenRouter interpreter of
Dev-008. Estimate from the documented price: 40 candidates is about 1.5k input tokens, about
$0.00006 per call (check against the bench).

## 5. What must not break

- The world engine is the only writer: Jev and the host propose, `Submit` validates and commits.
- One action API: a free-text action is the same `GameAction` a menu click would send, journaled.
- `EtherBound.Sim` has no reference to `EtherBound.Llm`, no `HttpClient`, no wall clock.
- Replay needs no network: `InputReplayRules` still passes with Jev absent.
- The key never reaches a frame, an event, a log line or a test snapshot.
- WASD, menus and the `V` radial menu behave the same with and without a key.
- `MoveHz` movement and the 1 Hz clock are not slowed by a pending call.

target, Jev gates for the storyteller, Agent tactics, relationship ambiguity, and talking to
Extras. Those need witnesses and knowledge first and belong to a later Dev.

## TL;DR

Jev is an HTTP service, so the "runtime" is a small C# client in a new `sim.llm` module that the
sim never references. Free text becomes one `choice` over the engine's own `Menu` entries; high
confidence submits the action through the normal API, medium asks, low does nothing, and a missing
key disables free text instead of guessing. The decision is logged as `llm.interpreted`, replay
never needs the network, and a bench with a written pass rule decides whether the thresholds hold.

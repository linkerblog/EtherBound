# Dev-022: Split the largest source files

[Refactor] [Tooling]

Five source files hold ~5,900 lines between them. An agent that edits one method has to read or
page through the whole file, two docs in flight collide on the same file, and plans cite line
numbers that go stale after every commit. This doc moves code along seams the files already have,
with **no behaviour change**: the same tests pass unchanged and the visual baselines are not
updated.

**Precondition:** `Dev-020` is committed and the working tree is clean. `Dev-021` has not started
implementation [Sec. 1, Order].

**Execution note:** The user authorized proceeding with the existing local Dev-020 changes. The
`MapScene.ts`, `App.tsx`, web-test and snapshot changes were preserved. Visual specs ran on isolated
ports with a throwaway database so the active launcher and save were untouched.

## 1. Decisions

| Topic | Decision | Why |
|---|---|---|
| Scope | The five files in F1–F5. `handling.py` (667, seven uniform handlers), `pixelart.js` (833, one pipeline) and `STYLEGUIDE.md` (UI-only, read on demand) stay | Each is already easy to navigate; splitting adds files without removing reading |
| Behaviour | Pure moves. Bodies change only where `self.x` becomes a parameter or `this.x` becomes a field of a collaborator. No renames of public symbols, no logic edits, no drive-by fixes | The test suite and baselines are the proof; any logic edit would weaken it |
| Order | After Dev-020 is committed, before Dev-021 starts. This doc rewrites the file pointers of the open docs [Sec. 3.6] | Dev-021 edits `MapScene`, `physics.py` and `world.py` heavily; it should land in the small files |
| Server imports | Importers of payload types switch to `etherbound.engine.payloads`; `world.py` does not re-export them | One import path per symbol keeps grep honest |
| BitCanvas | Classic scripts in load order, sharing top-level scope as today. A file's top-level statements may use only what earlier files define | Keeps `file://` and no build (F8) |
| Size guard | `scripts/check-sizes.mjs` lists source files over 600 lines. Warn-only, part of `check` | Makes regrowth visible without blocking a commit |
| Generated types | `CONTEXT.md` "Commands" notes: find a type in `schema.d.ts` by `grep` on its schema name, do not read the file | F6 costs context, not maintenance |

## 2. Out of scope

- `handling.py`, `pixelart.js`, `STYLEGUIDE.md` [Sec. 1, Scope]; test files (they mirror features).
- Any behaviour change, including the W/A/S/D capture bug in `PENDING.md`.
- `submit`, `ensure_world`, `new_game`, `set_goal`, `advance_time`, `set_clock` stay in
  `WorldEngine`: they are the engine's write path.

## 3. What changes

### 3.1 server.engine: `world.py` (~1052 → ~550)

- **New `engine/payloads.py`:** `ActorState`, `WorldState`, `ChunkLevelPayload`,
  `ObjectPayload`, `ChunkPayload`, `MenuPayload`, `WorldInfo`, unchanged.
- **New `engine/world_setup.py`:** module functions for `_sync_materials`, `_load_grid`,
  `_commit_world`, `_has_chunks`, `_delete_uncarried_objects`, `_commit_objects`,
  `_resolve_generator`, `_spawn_point`, `_standing_h_near`, `_spawn_event`, `_settle_actor`,
  `_create_extras`, `_commit_extra`, `_ensure_actors`, without the leading underscore. Each takes
  what it reads (`session`, `registry`, `catalog`, `grid`) as parameters; none receives the
  engine. Where a helper today mutates `self._load_cache` or `self._next_seq`, it returns the
  value and `WorldEngine` assigns it.
- **New `engine/menu.py`:** `build_menu(...)` holds the body of `menu()`. `WorldEngine.menu`
  keeps its signature and docstring and delegates; `routes/api.py` is untouched.
- `WorldEngine` keeps `__init__`, `_stamp_and_store`, `_load_object_index`, `_refresh_load`,
  `load_kg`, `_world_row`, `_carried`, every public method, `_complete_activities`,
  `_activity` and `_mind`.
- Import updates: `minds/extras.py`, `net/ws.py` and the tests that import `ActorState`
  (`test_engine.py`, `test_extras_brain.py`, `test_handling.py`) take payload types from
  `engine.payloads`. `PLAYER_ID` and `WorldEngine` keep their import path.
- `test_architecture.py` needs no change: the new files live under `engine/`.

### 3.2 server.engine: `ops/physics.py` (~896 → ~470)

- **New `ops/edges.py`:** `_sign`, `_cardinal`, `_canonical_edge`, `_edge_cell`,
  `_wall_bottom`, `_edge_reachable`, `_edge_for_step`, `_wall_blocking_step`, `_surface_h`,
  public (no underscore).
- **New `ops/damage.py`:** `damage_object(ctx, op, ...)`, `damage_wall(ctx, op, ...)`.
- **New `ops/travel.py`:** `travel(ctx, op, ...)`, `terrain_blocks`, `solid_object_at`,
  `actor_at`.
- `PhysicsHandler` and its six subclasses stay in `physics.py` and call the new functions with
  `self.op_name`. `ops/__init__.py` registration is unchanged.

### 3.3 web.game: `MapScene.ts` (~1360 → ~550)

- **New `terrainAtlas.ts`:** `buildTerrainAtlas(textures)` returns
  `{ maskOffsets, spriteKeys, sideKeys, wallKeys, objectFrames, objectSpriteKeys }`, plus the
  `ObjectFrame`, `ObjectFrameSet`, `PendingObjectFrame` types, `registerObjectFrame` and
  `readPixels`. `MapScene.create` calls it once and stores the result.
- **New `chunkRenderer.ts`:** class `ChunkRenderer` with `drawChunk`, the blitter helpers,
  `drawTop`, `drawSurface`, `drawTileObjects`, `drawObjectSprite`, `drawObjectPrism`,
  `restingSurfaceDrawn`, `drawMask`, `drawVertical`, `drawSideRun`, `drawFaceRun`, the wall
  methods (`isFrontWall` … `drawWallRun`), `shade`, `scaleColor`, `variant`, `materialColor`,
  `objectMaterialColor`, `layersFor`, `clearChunkLayers`, `chunkBounds` and the `ChunkLayers`
  type. Constructed with the scene (for `add`), the `ChunkStore`, the atlas and a `view` object
  whose getters return `viewerH`, `cutoff`, `nikoTile`, `animatedObjectIds`, `materials`,
  `objectKinds`. It owns `chunkLayers`.
- **`extras.ts`** gains `ExtrasLayer` (`sync`, `update`, `clear`, from `syncExtras`,
  `updateExtras`, `clearExtras`); **`physics.ts`** gains `PhysicsAnimator` (`animate`, `update`,
  `clear`). Both receive the scene and, for physics, the callback that marks dirty chunks.
- `MapScene` keeps lifecycle, input, network listeners, prediction, camera and zoom, viewer and
  cutoff, structures, the dirty queue and culling. `createGame`, `MapScene`, `ContextTarget`,
  `PlayerAnchor`, `Telemetry` keep their exports.

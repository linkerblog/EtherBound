# Dev-016: Context menu usability and accessibility

[Feature] [UI] [Accessibility] [Engine]

The right-click menu is hard to use. Measured on seed 0: it interleaves every object on a tile,
repeats identical names, shows state noise as disabled rows, draws unavailable text almost
invisible, runs off the bottom of the screen, and can only be opened by an exact right-click on an
isometric tile with no preview of which tile will be picked. This doc groups the menu by what each
entry acts on, shows the picked tile before and while the menu is open, gives the menu a full
keyboard path, and fixes its layout and contrast. The server still builds every entry; the client
still only renders (`docs/utils/STYLEGUIDE.md` [Sec. 8]).

Reference: `docs/utils/VISION.md` [Sec. 7] (generated menus); `docs/utils/STYLEGUIDE.md` [Sec. 8]
(context menu) and the accessibility rules ("every HUD action has a keyboard path", "colour is never
the only signal", "destructive actions use anchored confirmations"); `CONTEXT.md` (Menus contract).

## 0. Repo state (measured 23/09/2026, `WorldEngine.menu` on seed 0)

| Tile | Entries | Problem |
|---|---|---|
| Table with a bottle (137, 133, z 2) | 16 | `Take Table`, `Take Bottle`, `Drag Table`, `Drag Bottle`… catalog order interleaves the two objects |
| Two stacked chests (126, 127) | 9, all but 3 off | `Inspect Chest` twice, `Take Chest` twice: no way to tell upper from lower |
| Closed chest (124, 127) | 11 | `Close Chest · already closed` is noise, not a choice |
| Any | — | `Inspect` and `Climb` with no subject: the tile is implied, never named |

- `ContextMenu` (`web/src/ui/ContextMenus.tsx`) clamps with a fixed `window.innerHeight - 180`; a
  16-row menu is about 370 px tall and runs off screen, with no scroll.
- Unavailable rows use `--line-hi` (#3a3d47) on `--panel` (#0c0d10): about 1.7:1. Reasons are
  10 px `--dim`, squeezed to the right of the label.
- Rows are `<button disabled>`: they cannot be focused, so arrow keys land on rows that Enter
  ignores silently. No `role="menu"`; DOM focus never enters the menu.
- `MapScene` (`web/src/game/MapScene.ts`) picks only on `pointerdown` with the right button; no hover
  feedback. No key opens the menu.
- The menu is never refreshed: walking away leaves stale `available` flags.
- `break`, `hit` and `throw` (tags `violent`) sit among harmless ops with the same style.

## 1. Decisions

| Topic | Decision | Why |
|---|---|---|
| Grouping | The server adds `group` (stable key: `object:<id>`, `edge:<z>:<dir>`, `actor:<id>`, `tile`, `self`) and `group_label` to each entry, and returns entries sorted by group, then catalog order | One header per thing; the client never reorders |
| Group order | Tile objects from the top down (highest `h` first, then id), their open contents, walls, actors, the ground tile, `self`, held and worn objects | The top thing is usually what was clicked |
| Names | Duplicate names in one menu get a position: `Chest (upper)`, `Chest (lower)`; same `h` → `Chest 1`, `Chest 2` by id. Held: `Shovel (held)`, contents: `Apple ×3 (in Chest)`, ground: `Ground · Wood · 2 m`, walls: `Brick wall · north` | Every row can be told apart by reading |
| Row text | New `detail` from the handler: direction for push/pull/drag (`south`), `into Chest` for put, `×3` for a split take. Row = `label` + `detail`. `subject` stays for the feed | No string splitting in the client |
| State noise | `applies` is false when the target's own state rules the op out whatever Niko does (`open` on an open container, `close` on a closed one). `validate` keeps reasons Niko can change (reach, hands, weight, pause) | Disabled rows then always mean "you could, but not now" |
| Collapse | A group whose entries are all unavailable for one shared reason renders as a single row, `Chest (upper) · out of reach`, expandable with → or a click | 6 dead rows become 1 |
| Violent ops | Entries tagged `violent` go last in their group after a divider, with a `!` marker and `--yellow` text | Colour is never the only signal |
| Confirmation | New tag `destructive` on `break` only. The first Enter or click turns the row into `CONFIRM BREAK? ⏎`; a second within 3 s sends; anything else cancels | Anchored confirmation from the style guide, without slowing repeated `hit` |
| Hover | `MapScene` outlines the tile the pointer would pick (1 px `--cyan` diamond on its standing surface), and pins it on the menu's tile while the menu is open | You see the target before clicking |
| Keyboard | `E` opens the menu on the hovered tile, or on Niko's tile when the pointer is off the world; the `ContextMenu` key and `Shift+F10` do the same | STYLEGUIDE: every action has a keyboard path |
| Refresh | While open, the menu is fetched again (at most every 250 ms) when Niko changes tile, the target chunk changes, or an action result arrives; focus stays on the entry with the same `group` + `op` + `detail` | Rows never lie about availability |

## 2. Server (server.engine)

- `MenuEntry` (`engine/actions.py`): add `group: str`, `group_label: str`, `detail: str | None`.
- `OpHandler` (`engine/ops/base.py`): add `detail(ctx, action) -> str | None`, default None.
  Implement it in `physics.py` (directions), `handling.py` (`put`: `into X`; `take`/`drop`
  with a quantity: `×N`).
- `WorldEngine.menu` (`engine/world.py`, delegating to `engine/menu.py::build_menu`): compute each candidate's group key and label once,
  apply the naming rules in [Sec. 1], sort candidates in group order, then loop candidates first
  and ops second so entries come out grouped. Update the Menus contract in `CONTEXT.md`
  ("candidate order, then catalog order").
- `OpenHandler.applies` / `CloseHandler.applies` (`handling.py:458`, `:500`): add the state check;
  audit the other handlers for the same rule and list any change in the doc before coding it.
- `ops.toml`: add `destructive` to `break`'s tags.
- `MenuResponse.target` stays; the client shows it as the header.

## 3. Client

**web.game** (`web/src/game/MapScene.ts`)
- On `pointermove`, at most once per frame and only when the pointer moved, run `pickTile` and
  draw the outline; clear it when the pointer leaves the canvas.
- `setPinnedTarget(target | null)` keeps the outline on the menu tile.
- `tileScreenPosition(x, y, h)` returns page coordinates, used to anchor a keyboard-opened menu.
- `onContextMenu` also fires for `E` / `ContextMenu` / `Shift+F10`, with the hovered or own tile.

**web.ui** (`web/src/ui/App.tsx`, `ContextMenus.tsx`, new `menuModel.ts`, `styles.css`)
- `menuModel.ts` (pure): builds rows from entries (group headers, collapsed groups, violent
  divider, digit hints `1`–`9` for the first nine available rows) and `placeMenu(anchor, size,
  viewport)` (open at the cursor, flip left or up when it would overflow, clamp 8 px from edges).
- `ContextMenu`: `role="menu"` labelled by the header; rows `role="menuitem"` with
  `aria-disabled` (focusable, never the `disabled` attribute); headers `role="presentation"` inside
  `role="group"`. DOM focus moves to the first available row on open and returns to the previous
  element on close. Keys: ↑/↓ (skip headers), Home/End, → expands a collapsed group, digits pick,
  a letter jumps to the next row starting with it, Enter/Space pick, Esc/Tab close. An unavailable
  row picked by key or click stays open and pulses its reason (none under reduced motion).
- Layout: measured with `useLayoutEffect`; `max-height: calc(100vh - 16px)`, scroll with the
  focused row kept in view; width 220–320 px; rows at least 28 px tall, 13 px text.
- Colours: unavailable label `--dim`, reason on its own line at 11 px in `--text` at 70 % opacity;
  header shows `target` first and `x, y · z` second in `--dim`.
- Refresh logic from [Sec. 1] in `App.tsx`, keyed by the menu's target.

**docs**: `STYLEGUIDE.md` [Sec. 8] updated with the new rows, colours, keys and confirmation;
`CONTEXT.md` Menus contract.

## 4. What must not break

- The client never adds or removes an op; it sends back `entry.action` unchanged.
- `submit` still re-validates everything; the menu stays a lock-free read.
- Menus for tiles with one object or none look and behave as before, apart from the header.
- Opening the menu with `E` does not move Niko; WASD, zoom keys and Enter-to-input keep working
  when the menu is closed.
- The free-text input keeps its keys: `E` typed in the input does nothing to the menu.

## TL;DR

The server groups menu entries by what they act on (topmost object first), names duplicates
(`upper`/`lower`), adds a `detail` per row and drops state-noise entries like "Close · already
closed". The client shows the target tile on hover, opens the menu with `E`, gives it real focus,
ARIA roles and keys (arrows, digits, letters), collapses dead groups, puts violent ops last with a
marker, asks to confirm `Break`, keeps the menu on screen with scroll, fixes contrast and refreshes
it live.

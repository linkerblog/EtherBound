# Dev-015: Debug lab map and generator options

[Feature] [World] [Debug] [Tooling]

Map generation work needs a place to try one option at a time without walking the 256 m test
world or regenerating it by hand. This doc adds a second generator, `lab`: a small flat map made of
fixed reference bays around a central **feature bay**. The feature bay is where each new
generation option (relief, roads, buildings, later the city blocks) gets stamped. The server
describes each generator's options as data, the DEBUG drawer builds a form from that data, and
REGENERATE rebuilds the lab in about a second. The test world stays exactly as it is and stays the
default.

Reference: `docs/utils/VISION.md` [Sec. 5] (world model), [Sec. 11] (determinism); `CONTEXT.md`
(Data model, test world, pitfalls "Test-world changes require a generator version bump" and "Spawn
must come from the generator's road"); `docs/PENDING.md` (City authoring, NPC construction: both
lean on a seeded code generator, and this lab is where it is tried).

## 1. Decisions

| Topic | Decision | Why |
|---|---|---|
| Generators | A registry `GENERATORS` in `world/gen/registry.py`: `test` (existing, version 5) and `lab` (new, version 1). Each spec has `key`, `name`, `version`, an options model, `generate(seed, options, registry)` and `spawn(seed, options)` | One entry point for engine and API; the next generator (city) is one more entry |
| Save format | Migration `0007_generator` adds `world_meta.generator` (string, default `"test"`) and `world_meta.gen_options` (JSON, default `{}`) | Old saves open as `test` with no regeneration |
| Options | A Pydantic model per generator. `new_game` validates and stores the full dump, defaults included | `ensure_world` regenerates the same world from the row alone |
| Replay | `WorldGenerated` gains `generator` and `options` (defaults `"test"`, `{}` for old rows) | With options, the seed alone no longer names the world [VISION Sec. 11] |
| Spawn | `spec.spawn(seed, options)` is pure and cheap. `_spawn_point` uses it instead of `SPAWN_POINT` | A relocated actor on load must not run the generator |
| Option form | `GET /api/gen` returns every generator with a flat list of option fields (path, label, kind, default, min, max, step, choices, group). The client renders it, never writes a field by hand | Adding an option to the model makes it appear in the form |
| Features | `world/gen/features/`: each feature is a function that stamps into a rectangle through a small `GenCanvas`. The lab places the selected one in its feature bay. This doc ships one, `relief` | New options are written once and reused by the future city generator |
| Randomness | `relief` reads `ValueNoise(seed)` (stream `worldgen`), like the test world | Same seed and default parameters give the same shape as the test world's hills, a direct comparison |
| Regenerate | Uses `POST /api/game/new` (wipes actors, objects, log). No confirmation while the current generator is `lab`; the anchored confirmation stays when leaving any other generator | Nothing to lose inside the lab; a real save still needs the guard [STYLEGUIDE] |

The lab bays are a fixed test fixture, like the test world's building. The generated content lives
in the feature bay.

## 2. The lab map

4×4 chunks, 128×128 m. Base: grass at `h = 2`, strata as in the test world
(`topsoil 0, dirt 8, rock 24`). Asphalt paths 4 tiles wide at `x` and `y` in 0–3, 40–43, 80–83 and
120–123 form a grid; the border 124–127 is grass. That leaves nine 36×36 bays, at 4–39, 44–79
and 84–119 on each axis, numbered west to east, north to south:

| Bay | Key | Content |
|---|---|---|
| 1 | `steps` | Terraces 4 tiles deep rising west to east by Δh 1, 2, 3, 4, 6, 8 (0.5 m walk, 1–1.5 m climb, 2, 3, 4 m blocked), a 1:1 ramp up to +6 and a 6-step stair |
| 2 | `materials` | For each registered material in id order: a 4×4 patch at `h = 2` and next to it a 2×2 block at `h = 4` (to show its side sheet). Generated from the registry, so new materials appear on their own |
| 3 | `water` | A pool: shallow ring (`h − 2`), deep centre (`h − 4`), same rule as the test world pond |
| 4 | `structure` | A 10×8 brick building: west doorway, north windows, ground floor, first floor, roof with a stair hole, stairs between them. Same level encoding as the test world |
| 5 | `feature` | The feature bay: flat unless `options.feature` stamps something |
| 6 | `objects` | One of each catalog kind in catalog order, every 3 tiles on a row; containers hold one `apple`; two of the first `surface` kind stacked for climbing |
| 7 | `dig` | Flat ground plus a 6×6 pit 2 m deep with a one-tile ramp on its east side |
| 8 | `walls` | One 6-tile wall segment per building material (`tags` contains `building`) with a doorway and a window, and a chest in front of each for push tests |
| 9 | `open` | Flat grass kept empty for pushes and throws |

Spawn: on the path north of the feature bay, `(61.5, 41.5, h = 2)`, unless `spawn_bay` picks the
path tile north of another bay's centre.

### 2.1 Options (`LabOptions`)

| Path | Kind | Default | Range |
|---|---|---|---|
| `feature` | choice | `none` | `none`, `relief` |
| `spawn_bay` | choice | `feature` | the nine bay keys |
| `relief.amplitude` | int, half-metres | 12 | 0–24 |
| `relief.scale` | float, metres per noise unit | 96 | 8–256, step 8 |
| `relief.octaves` | int | 3 | 1–6 |
| `relief.gain` | float | 0.5 | 0.1–0.9, step 0.05 |
| `relief.edge` | int, tiles | 4 | 0–12 |

`relief` sets `h = 2 + round(fbm(x/scale, y/scale, octaves, gain) × amplitude)` inside the bay,
blended linearly to `h = 2` over the last `edge` tiles so the bay meets the paths at walking height.
`group = "relief"` on those fields tells the form to show them only when `feature == relief`.

### 2.2 Adding a feature later

1. A module in `world/gen/features/` with `stamp(canvas, rect, seed, options) -> list[GeneratedObject]`.
2. Its options model as a nested field of `LabOptions`, and its key in the `feature` choice.
3. Bump the `lab` version. Nothing in the client changes.

## 3. Changes by module

**server.world** (`world/gen/`)
- `registry.py`: `GeneratorSpec`, `GENERATORS`, `get_generator(key)`, `option_fields(model)` (walks
  the Pydantic model; `Literal` → choice, `bool`, `int`, `float` with `ge`/`le`/`multiple_of`, nested
  models → dotted paths with `group`).
- Rename `TestWorld` to `GeneratedWorld` (with `generator: str`); `generate_test_world` keeps its
  output byte for byte. `TestOptions` is an empty model.
- `canvas.py`: `GenCanvas(chunks_x, chunks_y, base_h, base_mat)` with `set_ground`, `set_surface`,
  `level(z)` edge and floor setters, and `build() -> GeneratedWorld`.
- `lab.py`: the bays in [Sec. 2]. `features/relief.py`.

**server.engine** (`engine/world.py`)
- `ensure_world(seed=0)`: read `meta.generator` and `meta.gen_options`; an unknown key falls back to
  `test` with a logged warning and regenerates. Regenerate when `meta.gen_version < spec.version`.
- `new_game(seed, generator="test", options=None)`: validate, store `generator` and the full options
  dump, generate through the spec. `_commit_world` takes `GeneratedWorld`.
- `_spawn_point` uses `spec.spawn(meta.seed, options)`.

**server.db**: `0007_generator` as above, `WorldMeta` fields.
**server.events**: `WorldGenerated.generator: str = "test"`, `options: dict = {}`.
**server.app** (`routes/api.py`): `NewGameRequest` gains `generator` and `options` (both optional;
invalid → 422 and the world untouched); `StateResponse` gains `generator`, `gen_version`,
`gen_options`; new `GET /api/gen` → `GeneratorInfo[]` (key, name, version, fields, and for `lab`
its bays with key and rectangle).

**web.net**: regenerated `schema.d.ts`; `requestNewGame(seed, generator?, options?)`, `fetchGenerators()`.
**web.ui**
- NEW dialog: a `MAP` select from `/api/gen` (default: the current generator).
- DEBUG drawer: the placeholder becomes a `MAP` tab: current generator, seed and version; the
  generated option form (select, number input with min/max/step, checkbox), groups shown only when
  their condition holds; the bay list with coordinates; `SEED` field with `RANDOM`, and
  `[ RESET ]` (defaults) and `[ REGENERATE ]`. A pure `web/src/ui/genForm.ts` turns fields and
  values into rows and back into nested options, so it can be tested in node.

## 4. What must not break

- `generate_test_world(seed)` output and `GEN_VERSION = 5`: existing saves do not regenerate and the
  seed-7 visual baselines stay identical.
- `POST /api/game/new {seed}` alone still gives the test world.
- One writer: generation runs only inside `WorldEngine.new_game` and `ensure_world`.
- Determinism: equal generator, seed and options give identical `blob_bytes()` and objects; no bare
  `random` (Ruff `TID251`).
- A `0006` save upgrades in place with no wipe.

## TL;DR

A second generator, `lab`: a 128 m flat map with eight fixed reference bays (steps, materials,
water, building, objects, dig, walls, open space) around a feature bay where new generation options
are stamped. Generators live in a registry; `world_meta` stores which one made the save and its
options (migration `0007`); the server exposes the options as data and the DEBUG drawer builds the
form and regenerates. The first option is `relief` (noise hills with amplitude, scale, octaves, gain,
edge blend). The test world does not change.

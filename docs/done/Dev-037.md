# Dev-037: Construction system, phase 2 (interior halves)

[Feature] [World] [Engine] [Rendering]

Extend `build` and `break` to the interior half-wall slots `H` and `V`. A half-wall divides one
tile into walkable regions; continuous movement, A* and the rendered world must agree about which
side an actor occupies and which tile edges that side can reach.

Reference: `docs/done/Dev-036.md` [Sec. 2] (slot geometry), [Sec. 4] (region-aware A*),
`docs/utils/VISION.md` [Sec. 5] (mutable space and pathfinding), `CONTEXT.md` (movement, action,
host and renderer contracts), `docs/utils/PITFALLS.md` [Sec. 2], [Sec. 3] and [Sec. 5].

## 1. Decisions

| Topic | Decision | Why |
|---|---|---|
| Target | Reuse `edge {x,y,z,direction}` with `direction = "H"` or `"V"` | Keeps the action catalog and its target kinds unchanged; these are wall slots, not a new op |
| Ownership | `H`/`V` belong to the addressed tile and are not canonicalized | Unlike north/south and east/west edges, an interior slot has no neighbouring owner |
| Storage | Set the existing `slot_mask` bit and `slot_mat` cell value | Dev-036 already shipped these fields and the `wall_slot` integrity key accepts slot names |
| Material | Every interior slot in a cell uses the same material | `slot_mat` is one material per cell; reject a later slot if the site material changed |
| Region graph | Four quadrants; connect across a half-line unless its `H`/`V` wall exists; neighbouring regions cross only through an aligned half-edge port | Exact for this phase; diagonal slots are still phase 3 |
| Movement | The body centre stays `BodyRadiusMetres + WallT/2` from an interior wall; perpendicular crossing blocks and parallel entry is moved to the nearest side | Prevents walking through or along a wall, including centre-aligned paths |
| Navigation | Search nodes retain `(Spot, region)`; legacy `FindPath` still returns spots, while Extras retain region-bearing waypoints and align on the shared port before crossing | A* and the actual continuous body must agree on which half of an edge is reachable |
| Diagonals | A* uses cardinal transitions if an endpoint or either L-route middle tile is split | The equivalent two-leg route is explicit and avoids inventing a quadrant at a corner |
| Build reach | The tile itself or an orthogonal neighbour; an actor whose body overlaps the wall height and line blocks construction | The wall is inside one tile, not on a shared edge |
| Picking | A ray hits an interior slot only when its wall exists | Avoids stopping on every tile's centre line in open rooms; bare slots remain available in generated menus |
| Damage | `hit`/`break` use `wall_slot` keys `H`/`V`; breaking clears only that slot bit | Uses existing sparse integrity and event flow |
| Rendering | Draw centered 0.25 m boxes, in wall face codes 3/4 and the existing wall height band | Interior walls are built geometry, not natural terrain cutaway material |

## 2. Scope

1. Build an `H` or `V` wall in a loaded tile band. Validate material, reach, duplicate slot,
   headroom and actors; persist its mask/material, emit `wall.built`, and bump the chunk revision.
2. Offer bare `H`/`V` slots in the generated menu and existing slots as physics targets. Pick an
   existing interior wall at its actual centre line.
3. Block continuous movement through an interior wall with body-radius clearance. Movement along a
   wall and entry exactly on its centre line must resolve deterministically to one side.
4. Compute per-height connected regions from the active `H`/`V` bits. A* carries regions, checks
   which boundary quadrants each region touches and can enter every region that touches the entry
   edge. `ExtrasBrain` supplies the actor's actual start region and follows a point inside each
   region rather than blindly aiming for tile centres.
5. Let physics damage and break interior walls using the existing `wall_slot` table.
6. Carry `slot_mask`/`slot_mat` through the detached host frame and draw both wall orientations.

Diagonals `D1`/`D2`, structural support/collapse, doors on interior slots, changing `slot_mat` to
per-slot storage, and NPC construction planning remain out of scope.

## 3. What must not break

- Edge-wall ownership, doors, windows and canonical north/west storage remain unchanged.
- Worlds without interior slots keep the existing A* neighbour order and path output.
- A blocked or partial build changes no geometry; completion, its event and its chunk revision commit
  together.
- Movement remains authoritative in the sim; Godot consumes only detached frame data.
- Interior walls use wall codes, so the natural-terrain cutaway never erases them.
- No migration is needed: `slot_mask`, `slot_mat` and `wall_slot` shipped in Dev-036.

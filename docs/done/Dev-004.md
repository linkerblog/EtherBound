# Dev-004: Camera zoom (Web client)

[Feature] [UI] [Input]

Lets the player change the camera zoom with the mouse wheel or the keyboard, in whole steps only,
so the placeholder tiles (and the LimeZu art that replaces them) stay crisp. Today the zoom is set
once in `MapScene.create()` from `devicePixelRatio` and never changes: on a normal monitor it is
fixed at x2, so a 1 m tile is 64 px and a 1080p screen shows about 30×17 m. Only the web client
changes. The server, the protocol and the schema stay as they are.

Reference: `docs/STYLEGUIDE.md` [Sec. 4] (integer zoom) and [Sec. 16] (keyboard path),
`CONTEXT.md` (web.game, radius-2 chunk streaming). `VISION.md` is not affected: the camera stays
top-down 3/4.

## 1. Decisions to approve

| Topic | Decision | Why |
|---|---|---|
| Levels | Whole steps only: **x1, x2, x3, x4**. Nothing fractional, at rest or during a change | The style guide's crispness rule. x1 is new: it doubles the visible area of today's default |
| Minimum | x1 (a 1 m tile is 32 CSS px) | Going below x1 needs a fractional zoom or a coarser map render, and at 4K it would show more than radius-2 streaming loads [Sec. 3.5] |
| Default | The saved level if there is one, otherwise today's rule `clamp(floor(devicePixelRatio), 2, 4)` | Nobody's first view changes |
| Persistence | The chosen level goes in `localStorage` (`etherbound.zoom`), read and written inside try/catch | It is a view preference of this browser, not world state: it never reaches the server |
| Anchor | The zoom stays centred on Niko (the camera keeps following him), not on the cursor | Zooming towards the cursor would fight the follow camera, which pulls back to Niko within a second anyway |
| Transition | Instant switch, no tween | A tween passes through fractional zooms. Instant also respects `prefers-reduced-motion` without extra code |
| Inputs | Wheel: up zooms in, down zooms out. Keys: `+`/`=`/numpad `+` zoom in, `-`/numpad `-` zoom out, `0` goes back to the default | Style guide [Sec. 16]: every HUD action has a keyboard path |
| Browser zoom | Ctrl/Meta + wheel and Ctrl/Meta + `+`/`-`/`0` are ignored by the game and left to the browser | Otherwise one gesture would zoom the page and the game together |
| HUD | A `ZOOM x2` line in the telemetry panel, below `SPD` | You can see the current level. No zoom buttons: wheel and keys cover it |

## 2. What gets built

### 2.1 `web/src/game/zoom.ts` (new, pure, no Phaser import)

```ts
export const ZOOM_LEVELS = [1, 2, 3, 4] as const;
export type ZoomLevel = (typeof ZOOM_LEVELS)[number];

export function defaultZoom(devicePixelRatio: number): ZoomLevel;   // clamp(floor(dpr || 2), 2, 4)
export function stepZoom(level: ZoomLevel, steps: number): ZoomLevel; // clamps to [1, 4]
export function loadZoom(fallback: ZoomLevel): ZoomLevel;           // localStorage, validated
export function saveZoom(level: ZoomLevel): void;                   // localStorage, errors swallowed

/** Turns raw wheel deltas into whole steps; trackpads send many small deltas per gesture. */
export class WheelAccumulator {
  push(deltaY: number, deltaMode: number, now: number): number;     // returns steps: -n..+n, usually 0 or ±1
}
```

- `loadZoom` accepts only a stored value that is one of `ZOOM_LEVELS`. Anything else (missing,
  `"2.5"`, garbage, or a storage exception) returns `fallback`.
- `WheelAccumulator`: convert the delta to pixels (`deltaMode` 0 = px ×1, 1 = lines ×40,
  2 = pages ×800), then add it to a running total. The total resets when the sign flips or when
  more than 250 ms have passed since the last push. Every full 100 px emits one step and subtracts
  100 from the total. Negative `deltaY` (wheel up) gives a positive step (zoom in). A mouse notch
  (100 px in Chromium, 3 lines in Firefox) is exactly one step, and a trackpad swipe is a few.
- The `now` argument is `performance.now()` from the caller, which is presentation-side input
  timing like the 20 Hz movement. It never reaches the simulation, so the determinism rule does not
  apply.

### 2.2 `web/src/game/MapScene.ts`

- Remove `integerZoom()`. Add a `zoom: ZoomLevel` field and a new option
  `onZoom: (level: ZoomLevel) => void` in `MapSceneOptions`.
- `create()`: `this.zoom = loadZoom(defaultZoom(window.devicePixelRatio))`, then `applyZoom()`.
- `applyZoom(level)`: if the level has not changed, return. Otherwise
  `this.cameras.main.setZoom(level)`, store it, `saveZoom`, `onZoom(level)`. Also call `onZoom`
  once at the end of `create()` so the HUD shows the starting level.
- Wheel: `this.input.on("wheel", (pointer, _objects, _dx, dy) => ...)`. If `pointer.event.ctrlKey`
  or `metaKey` is set, return. Otherwise feed `dy` and `(pointer.event as WheelEvent).deltaMode` to
  the accumulator and call `applyZoom(stepZoom(this.zoom, steps))`. Phaser already registers the
  canvas wheel listener as non-passive with `preventDefault`. The HUD panels sit above the canvas
  with `pointer-events: auto`, so the wheel does nothing over them, which is intended.
- Keys: `this.input.keyboard!.on("keydown", (event: KeyboardEvent) => ...)`. Use the same guard as
  `readDirection()` (ignore while an `input`/`textarea` has focus) and ignore Ctrl/Meta/Alt.
  `event.key` `+` or `=` zooms in, `-` zooms out, `0` resets to `defaultZoom(devicePixelRatio)`.
  Numpad keys produce the same `key` values. Match on `event.key`, not key codes, so non-US layouts
  work.
- Right-click is unchanged: `pointer.worldX/worldY` already account for the camera zoom
  [Sec. 3.3].
- `createGame(...)` gets an `onZoom` parameter and passes it into the scene options.

### 2.3 `web/src/ui/App.tsx` and `styles.css`

- `const [zoom, setZoom] = useState<number | null>(null)`, passed to `createGame` as `setZoom`.
- In the telemetry panel, add a third readout row: `ZOOM` / `x{zoom}`. Same `.readout` markup and
  styles, so no new CSS. The `ZOOM` label fits the 32 px label column at 11 px mono. If it clips,
  widen the column to 36 px. That would be the only CSS change.

### 2.4 Docs

- `docs/STYLEGUIDE.md` [Sec. 4]: change "(x2, x3, x4)" to "(x1 to x4; wheel and `+`/`-`/`0`)".
- `CONTEXT.md`, web.game row: add "integer zoom x1–x4 (wheel, `+`/`-`/`0`, saved per browser)".

## 3. Traps

1. **Fractional DPR.** Windows scaling at 125 % or 150 % makes `devicePixelRatio` 1.25 or 1.5. The
   Phaser canvas is sized in CSS pixels and the browser rescales it, so pixels are uneven at every
   zoom level. This bug already exists and this doc does not fix it. Fixing it means a DPR-aware
   canvas, which is its own change. Record it in `docs/PENDING.md` under Loose ends.
2. **The follow lerp.** `startFollow(..., 0.12, 0.12)` recentres smoothly after a zoom change.
   Phaser zooms around the viewport centre, so Niko stays centred and needs no manual scroll fix.
   Do not call `centerOn` after zooming: it breaks the lerp and snaps the view.
3. **Stale `worldX`.** `pointer.worldX` updates only on pointer events. The right-click handler
   reads it inside a `pointerdown`, so it is fresh. Do not reuse a cached pointer position from
   before a zoom change anywhere else.
4. **Streaming radius at x1.** The hub sends chunks within radius 2, which covers at least 64 m
   from Niko in every direction. At x1 half the viewport is 30 m (1920 px), 40 m (2560 px) or 60 m
   (3840 px), so there are no empty edges up to 4K at DPR 1. Anything below x1 would need a wider
   radius on the server; that stays out of scope.
5. **Camera bounds.** `setBounds` works in world pixels and Phaser applies the zoom when it clamps.
   At x1 the viewport can reach the world edge (the test world is 256 m). Phaser clamps there, and
   Niko is simply off centre near the border. That is expected, not a bug.
6. **Strict Mode double mount.** `main.tsx` renders under `StrictMode`, so the game is created,
   destroyed and created again in development. Keyboard and wheel listeners attached through
   `this.input` go away with the scene. Do not attach them to `window`.

## 5. What must not break

- WASD movement, prediction and reconciliation: zoom touches only the camera.
- Right-click on a tile opens the menu for that exact tile at every zoom level.
- Typing `+`, `-`, `=` or `0` in the free-text input puts the character in the input and leaves
  the zoom alone.
- Ctrl + wheel and Ctrl + `+`/`-`/`0` still zoom the page as usual. The game ignores them.
- The browser context menu stays suppressed (v0.1.3 behaviour).
- First load on a clean browser shows the same zoom as before this change.

## 6. Tests and checks

The web client has no test runner, and adding one is out of scope. `zoom.ts` is kept pure so a
later runner can cover it directly. Checks:

```text
cd web && npm run build
cd server && uv run pytest && uv run ruff check && uv run ruff format --check && uv run pyright
```

The server checks are unaffected and are only run to confirm that. Manual acceptance, with
`EtherBound.exe`, in Chromium and Firefox:

1. Clear `localStorage`, then load: the zoom equals the old default (x2 on a DPR-1 screen) and the
   HUD shows `ZOOM x2`.
2. One mouse-wheel notch up: x3. Another: x4. More notches: stays at x4. Wheel down to x1, then
   stays there. Each notch moves exactly one level.
3. A slow trackpad swipe moves one or two levels, not four at once.
4. `+`, `=`, numpad `+`, `-`, numpad `-` step the zoom, and `0` returns to the default.
5. With the free-text input focused, those keys type characters and the zoom does not change.
6. Ctrl + wheel zooms the page and the game level does not change.
7. At x1 and at x4, right-click the doorway tile of the test building. The menu's `TILE x,y,z`
   matches the tile under the cursor.
8. At x1, walk to every edge of the loaded area. No black gaps inside the world bounds.
9. Reload the page and the last level is kept. In a private window it falls back to the default
   without errors in the console.
10. The wheel over the HUD panels (feed, meters, input line) does nothing.

## TL;DR

Adds whole-step camera zoom from x1 to x4 to the web client: mouse wheel (with an accumulator so
trackpads do not skip levels) and `+`/`-`/`0`. Ctrl combinations are left to the browser, and
the zoom does nothing while typing. The zoom stays centred on Niko, switches instantly with no
fractional frames, is saved per browser and shows as `ZOOM xN` in the telemetry panel. x1 is new
and doubles the visible area, still inside radius-2 streaming up to 4K. The first-load default
does not change. Only `web.game` (v0.0.6) and `web.ui` (v0.0.5) change. Nothing on the server,
protocol or schema. The existing blur at Windows 125 %/150 % scaling is recorded in PENDING, not
fixed here.

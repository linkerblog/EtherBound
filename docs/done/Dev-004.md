# Dev-004: Game UI layout, build panel and dev console

[Feature] [UI] [Rendering]

Replace the old top-bar HUD with the layout designed in Figma: a left menu column, a fixed game
viewport, a status column, a build panel that opens inside the viewport (walls and floors), and a dev
console shaped like a web page. The design is the source of truth for layout, spacing and colors; the
sim stays the source of truth for every number shown.

Design source: Figma file `EtherBound-Design` (fileKey `3YuCVE3naRWrwL8Xhvvzdg`), 2560×1440 frames
`HUD / Base` (11:53), `HUD / Build Open (Walls)` (7:72), `HUD / Build Open (Floors)` (7:112) and
`Debug / Web Page` (8:46), colors in the variable collection `EtherBound/Colors`.

## 1. Findings

- `game/ui/GameHud.cs` was a top bar with `GAME`/`DEBUG`/`LLM` views on ALT+1/2/3 plus clock, pause,
  speed, feed, carry, activity, input line, compass and FPS, all scaled by a fixed `UiScale = 1.5`
  against a fixed 1280×720 window: the design is 2560×1440, which is 2× the window, not 1.5×.
- `WorldClient` read bare `W`, `A`, `S`, `D` for movement and `T`, `C`, `X`, `O`, `H`, `V`, `1`, `2`,
  `4` for view toggles. The design labels the menu `[G]AME`, `[I]NVENTORY`, `[D]EBUG MENU`, so a bare
  `D` would collide with moving right.
- `PixelView` sized its `SubViewport` and its `TextureRect` from the whole window and positioned the
  texture from the art-pixel remainder alone, so the world rendered edge to edge under the HUD with
  no rectangle to render into. `RayFromScreen` maps from `_display.GlobalPosition`, so moving the
  texture also moves picking.
- The `build` op accepts `tile` and `edge` targets and takes **no material argument**: the material is
  the surface the build stands on, and a surface without `build_cost` is refused. `Menu.Build`
  returns the entries, `MenuEntry.Subject` is the sim's own "<Material> wall"/"<Material> floor".
- The sim exposes no HP or EP, so the design's `StatBar` components have nothing to read.
- `game.tests/` exists and runs with xunit against the game assembly plus `GodotSharp`; its tests
  cover pure functions and need no engine. Frame arithmetic can therefore be asserted automatically.
- `WorldFrame.Actors` carries name, kind, position, height and activity for a read-only NPC list.

## 2. Decisions

Taken as the plan's proposals; the two that the plan flagged are noted.

- **D1. Design space.** The HUD lays out in 2560×1440 units and scales by `window height / 1440`
  ([Sec. 3.1]), replacing `UiScale = 1.5`. The 720p default window renders 24-unit text at 12 px,
  which the plan accepted; `game.app` keeps its 1280×720 default window.
- **D2. Hotkeys.** ALT+1/2/3 stay and are shown in the menu labels: `GAME  ALT+1`,
  `INVENTORY  —` (disabled), `DEBUG MENU  ALT+2`. No bare letter is a hotkey.
- **D3. Existing panels.** Adopted as proposed: clock, pause, speed and `NEW` in the header; feed and
  input in the footer right of `BUILD`; activity and carry in the status column; compass inside the
  viewport; the LLM placeholder in the viewport area. The plan's follow-up — update Figma with these
  panels and export the tokens — was not done: this session had no Figma access [Sec. 6].
- **D4. HP and EP.** No bars with invented values: the status column holds a `STATUS` panel that is
  never shown. Tracked in `docs/PENDING.md` until a sim Dev exposes vitals.
- **D5. The build panel is a filter over the existing action.** `Menu.Build` decides the subjects,
  `WALLS`/`FLOORS` are its `edge`/`tile` target kinds, and a click resolves the armed slot against the
  menu the sim returns for the clicked ray and submits that entry's own `GameAction`. Nothing is
  constructed on the client and there is no second path around the action API.
- **D6. Dev console technology.** Godot `Control` nodes styled as a page, reusing `GeneratorPanel` and
  the existing `NewGameRequested` path. No web view and no local HTTP server.
- **D7. Inventory.** Shown disabled until its screen is designed. `LLM` stays on ALT+3.

## 3. Scope as built

### 3.1 Stage 1: layout shell

- `game/ui/HudTheme.cs`: colour, font and stylebox tokens in one place, from the `EtherBound/Colors`
  values documented in `docs/utils/STYLEGUIDE.md` [Sec. 3]; `Scale` is set by the shell and every
  size is expressed in design units. No hex literal is left in `game/ui/`.
- `game/ui/HudLayout.cs`: the frame's arithmetic with no nodes — 2560×1440, 32-unit margins, 40-unit
  gutters, `Header` 64, footer 80, menu column 200, `GameViewport` 1920×1152 (30×18 tiles of 64),
  status column 296, `BUILD` 200×80, feed 1456, input 760×40, compass 160. The header, footer and
  status widths are derived so the frame sums exactly to 2560×1440; confirm them against Figma.
- `game/ui/GameHud.cs`: the shell only — header, left `MainMenu`, `GameViewport`, status column,
  footer, plus the console and the LLM placeholder as sibling pages over the world.
- `game/spike/PixelView.cs`: `SetTargetRect` renders the world into the `GameViewport` rectangle,
  `SetBackdrop` paints the page behind it. Mouse input reaches the world only inside the rectangle;
  keyboard movement is not gated by it.
- The `Pause`, speed, `NEW`, feed, input, carry, activity, compass and menu controls keep their
  existing events and wiring.

### 3.2 Stage 2: build panel

- `game/ui/BuildPanel.cs`, docked at the bottom of the viewport: `WALLS`/`FLOORS` tabs, one
  `BuildSlot` per subject `Menu.Build` returned, with normal, hover, selected and disabled states.
- `BuildButton` toggles it. Opening it leaves `CanMoveWorld` alone, so movement keeps working; Esc
  closes it and disarms the slot. A slot with no matching entry for the clicked target reports
  `CAN'T BUILD HERE` in the feed instead of guessing an action; an unavailable entry reports the
  sim's own reason.

### 3.3 Stage 3: dev console

- `game/ui/DevConsole.cs`, opened in the viewport area by `DEBUG`: top bar with seed and tick, sidebar
  (World, NPCs active; Events, Clock, Save disabled), `REGENERATE WORLD` card around
  `GeneratorPanel` and an NPC table.
- `Regenerate` raises the same `NewGameRequest` the rest of the client uses; the client mutates
  nothing. The table's columns are `WorldFrame.Actors` fields only.

## 4. What must not break

- The client never simulates: the HUD reads `WorldFrame` and raises events; only `WorldEngine` writes
  state. `sim/` is untouched.
- One action API: the player builds through the same `build` op as every actor, and only through the
  entry the sim returned for the clicked target.
- Existing keys: `W`, `A`, `S`, `D`, `T`, `C`, `X`, `O`, `H`, `V`, `1`, `2`, `4` and ALT+1/2/3.
- Pause, speed, feed, input line, carry, activity, compass and the LLM placeholder still work.
- Determinism and saves: no schema change, no migration.

## 5. Acceptance

- **A1.** `game.tests/HudLayoutTests.cs` asserts the frame at 2560×1440 and at 1280×720: margins,
  gutters, the 200×50 menu with its 21 gap, the 1920×1152 viewport as 30×18 tiles of 64, the footer,
  the compass and the scale. Matching the Figma frame pixel for pixel stays `manual`; the captures at
  the design size are `docs/PENDING.md`.
- **A2.** Menu and build button states are styled from `HudTheme` and captured by
  `npm run shots`-style runs at 2560×1440: `spawn-x2.png`, `build-walls.png`, `build-floors.png`,
  `build-selected.png`, `dev-console.png`, `dev-console-npcs.png`, `llm-placeholder.png`. The
  selected slot cannot be shown in the default test world, whose surfaces offer no buildable
  material, so it stays `manual` in `docs/PENDING.md`.
- **A3.** The panel lists exactly the entries `Menu.Build` returned for the player's tile and its open
  neighbours — at seed 7 that is one disabled `Asphalt wall` slot with the sim's own reason — and
  submits the entry's own action. `sim/EtherBound.Sim.Tests/BuildRules.cs` covers the op; the click
  path is `manual` for the same reason as A2.
- **A4.** `Regenerate` raises `NewGameRequested`, the path the header's `NEW` already used;
  `Goldens.cs` is unchanged and `npm run check` passes.
- **A5.** `SendMovement` is unchanged and still gated only by `CanMoveWorld`, never by the viewport
  rectangle; `manual` in `docs/PENDING.md`.
- **A6.** The sim assembly is untouched: `Architecture.cs` and `npm run check` pass.

## TL;DR

The HUD is the Figma layout: a 2560×1440 design space scaled by window height, a left menu, a
`GameViewport` the world renders into, a status column and a footer with `BUILD`, feed and input. The
build panel and the console are filters and readers over the sim's own menu, frame and generator — no
new action path and no state written on the client. The Figma frames themselves were not reachable
from this session, so the palette comes from the documented tokens and the frame's derived widths are
a manual check.
